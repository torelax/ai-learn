# ColQwen 系列补充解读

模型报告见 [ColQwen 系列详解](ColQwen系列详解.md)。

## MaxSim 保留了什么，又忽略了什么

每个查询向量可以找到自己的局部证据，适合页面里多个词或区域共同支持查询。但求和本身不强制证据的空间关系，也可能让不同区域分别满足条件，却没有构成同一个事实。骨干的上下文化可以缓解这一问题，不能保证完全消除；复杂表格关系仍适合追加交叉编码器验证。

## 动态分辨率是容量分配

宽高比保持减少页面变形，更多 patch 让小字更可见，但也增加 token 数。以 1,280×320×2 字节估算，一页原始 bf16 向量约 0.82 MB，百万页约 0.82 TB，尚未计算索引结构。即使比高维多向量模型省很多，它仍不是单向量的存储量级。

## 处理器升级为何可能破坏旧索引

查询前缀影响 token 序列及上下文，图像预处理影响 patch 网格，mask 决定参与 MaxSim 的 token。只固定权重不能固定编码函数。实务上应把权重 revision、processor revision、模板、视觉预算和投影维度一起标记为一个索引版本，并在升级时用一批固定查询比较排序。

## 与 Qwen3-VL-Embedding 的选择

若普通 ANN 集成、存储和吞吐优先，可从单向量起步；若页面局部细节决定相关性，多向量值得评测。也可以单向量召回后对较小集合使用 MaxSim，但必须先确认召回集合覆盖所需页面。模型卡上的压缩倍数和榜单成绩应回到相同页面预算、任务集合及硬件后再做决策。

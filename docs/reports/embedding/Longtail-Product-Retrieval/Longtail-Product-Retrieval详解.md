# 长尾电商商品检索详解：离线改写蒸馏成原查询–商品对

> **paper**：[Synthetic Data Powers Product Retrieval for Long-tail Knowledge-Intensive Queries in E-commerce Search](https://arxiv.org/abs/2602.23620)（Ling et al.；SIGIR ’26；arXiv:2602.23620v2，2026-04-27）
> **venue**：SIGIR 2026，Melbourne；DOI [10.1145/3805712.3808409](https://doi.org/10.1145/3805712.3808409)
> **backbone**：改写与过滤器 Qwen3-30B-A3B；稠密检索 Tbstars-3B；业务相关性 Tbstars-42B-A3B（MoE）
> **date**：2026-04（会议 2026-07）
> **modality**：电商商品检索（query → product）
> **languages**：淘宝中文搜索日志；论文举例含中英查询

全文逐段中英对照见同目录 [zh.md](zh.md)。本文把方法、损失、过滤链和四张表的口径写清，数字只取论文表内原值。

**长尾查询（long-tail query）**：日志里出现很少的问法，几乎没有可靠点击或标注。**知识密集型查询（knowledge-intensive query）**：要先懂领域事实或多跳关系，才能知道该检索什么商品。论文例子是「蚂蚁上树的配料是什么？」——先知道这道菜的食材，再映射到商品。**多候选改写（multi-candidate rewriting）**：不是只扩一条同义说法，而是一次产出一组改写，每条覆盖一种说得通的子意图。**分布偏移（distributional shift）**：改写后的文本分布偏离用户真实查询，也偏离商品标题；若把改写器直接挂到线上扩召回，增量召回有限，还可能引入无关商品。**SBS（Side-By-Side）**：对照桶与实验桶的搜索结果页并排，标注员盲评。

## 这篇实际在做什么

商品检索为每条查询从数十亿商品里取出高召回候选，后面的排序都建在这批候选上。主流查询已经优化过。长尾、知识密集的查询仍然差：语言多样、购买意图不写明、需要领域推理，行为日志又少，人工标注贵。

常见补救是查询改写：把稀有问法映射成模型更熟的高频说法。论文认为这不够。检索器要学的是「这种意图对应哪些商品」。改写即使语义等价，训练里没见过类似商品关联，下游仍然召不回。改写还会漏掉约束，或把意图带偏。没有把改写和真实商品接上的标注，改写变好不会变成检索变好。

因此本文不把改写器部署上线。做法是：离线训一个强的多候选改写模型，用生产检索栈把改写捞到的商品挂回**原始查询**，滤成查询–商品对，再把这些对混进在线检索器的训练。线上仍只跑原来的检索栈。

| 项 | 论文设定 |
| --- | --- |
| 改写模型 | Qwen3-30B-A3B 初始化；5K 人工改写上 SFT，再多奖励 RL |
| 推理 | 每条查询至少 5 条候选改写 |
| 稠密检索 | 与线上相同的 Tbstars-3B；改写查询 ANN 取 top-200 |
| 业务相关性 | Tbstars-42B-A3B，业务规则标注上训练 |
| 改写分类器 / 通用相关性 | 未微调的 Qwen3-30B-A3B |
| 合成规模 | 约 400K 查询 → 约 20M 对 |
| 离线对照训练 | 两边都用 Tbstars-3B、同样 200M 规模；差别只在有没有长尾合成数据 |

## 改写：从保守扩召变成覆盖子意图

一般电商里，改写和原查询一起做候选扩展，行为故意保守，避免无关变体灌进下游。长尾知识密集查询不能只扩同义说法，因为相关商品依赖推理或外部知识。改写的目的变成：用一组候选改写替换原查询，合在一起覆盖完整意图空间。

训练两段。

1. **SFT。** 用 Qwen3-30B-A3B 从真实用户查询生成少量改写对，按业务规则人工审核清洗，得到约 5K 条标注，训出能写语义一致改写的基线。
2. **RL。** 每轮采样多个响应，每个响应是一列改写。三路连续奖励加权求和后更新。标准格式奖励始终存在，格式不对时多奖励不激活。

### 查询语义相关性

QSR 问改写有没有保住原意图。不在 RL 里再请人标，而是用 SFT 数据里已经标好的正/负 \<query, rewrite\> 训一个 LLM 二分类器。奖励是「相关」这一档的置信度：

$$
R_{\mathrm{QSR}} = p_{\mathrm{yes}} = \frac{\exp(z_{\mathrm{yes}})}{\exp(z_{\mathrm{yes}})+\exp(z_{\mathrm{no}})}
$$

### 商品侧分布对齐

PDA 把改写拉向商品标题、标签那类说法，而不是只像用户问句。在商品领域语料上对 LLM 做持续预训练（continued pre-training），得到商品表达分布。改写的困惑度越低越对齐，奖励取倒数：

$$
R_{\mathrm{PDA}} = \frac{1}{\mathrm{PPL}} = \exp\left(\frac{1}{T}\sum_{t=1}^{T}\log p(x_t \mid x_{<t})\right)
$$

### 多样性

每条查询看 $k=5$ 条改写。$n_i$ 是第 $i$ 条改写的字符 bigram（$n=2$）。奖励是两两 Jaccard 距离的平均，避免五条改写挤在同一种说法上：

$$
R_{\mathrm{Diversity}} = \frac{1}{\binom{k}{2}} \sum_{i<j}\left(1 - \frac{|n_i \cap n_j|}{|n_i \cup n_j|}\right)
$$

### 更新

三路都是连续值，用 REINFORCE++（策略梯度）而不是离散奖励的算法：

$$
\mathcal{L}_{\mathrm{RL}} = -\mathbb{E}\big[R_{\mathrm{total}}\cdot\log p(\mathrm{rewrites}\mid\mathrm{query})\big]
$$

$$
R_{\mathrm{total}} = \alpha R_{\mathrm{QSR}} + \beta R_{\mathrm{PDA}} + \gamma R_{\mathrm{Diversity}}
$$

$\alpha,\beta,\gamma$ 启发式取 $1.0,\ 0.5,\ 0.1$。RL 一直做到奖励大体收敛。

表 3 单独看 PDA。现成 Qwen3-30B-A3B 的改写人工准确率是 39.6%。任务优化但去掉 PDA：准确率 67.5%，商品侧 PPL 1407.4，检索 Item Goodrate 54.1%。加上 PDA：准确率 70.9%，PPL 降到 134.5，Item Goodrate 升到 72.8%。PPL 下降和召回商品变好是同一件事：改写更像商品语言，检索器才接得住。

## 离线检索：改写只用来造对，监督落在原查询上

改写之后数据量会爆。流水线按这个顺序收：

**改写分类器。** 接在改写模型后面，用业务规则摘要写成的轻量提示，输出 relevant / partially relevant / irrelevant，丢掉 irrelevant。策略是保守、高召回，少误杀。模型是未微调的 Qwen3-30B-A3B。

**检索。** 与线上相同的 3B 稠密检索器，在淘宝历史行为上训练。每条改写编码后对商品库做 ANN，取 top-200。

**相关性，两级。** 改写召回的商品与**原始查询**配对，不是与改写文本配对。业务模型是 42B MoE，在大规模业务规则标注上训练，对长尾知识密集查询泛化较好，但会偏向词面重叠，把词相同、意图不同的对标成相关。论文的例子：查询 “portable power station for camping” 和标题 “power station maintenance tool” 共享关键词，意图不同。因此再加一个通用语义模型（同样是未微调的 Qwen3-30B-A3B），用与改写分类器一样的保守高召回过滤，抓住这类假正例，同时少丢可能有效的对。

约 400K 查询收成约 20M 对。这 20M 对进入检索模型训练；改写器不进在线服务。

## 四类查询，两套 Goodrate

为了看模型在哪种意图上动，长尾知识密集查询分成四类：

| 类型 | 含义 | 论文例子 |
| --- | --- | --- |
| Question-Answering | 问句，要事实或解释 | What medicine can turn hair black? |
| Affordable Alternative | 找高端商品的平价替代 | Affordable alternatives to Converse shoes |
| Negative Expressions | 带否定约束 | Short sleeve shirt that doesn’t attract hair |
| General Knowledge | 其余仍要外部知识的查询 | Best GPU for Black Myth: Wukong |

离线和在线的 Query Goodrate **不是同一个定义**。

- **离线 Item Goodrate**：每条查询在召回集合里高度相关商品的比例，再对查询平均。
- **离线 Query Goodrate@N**：top-200 里至少有 $N$ 个相关商品的查询所占比例。每类从淘宝在线日志抽 500 条，人工标 query–item 相关性。
- **在线 Query Goodrate**：页面级。SRP 上 top-10 按展示商品相关性被标成 Good 或 Mid 的查询比例。同样每类 500 条。
- **GSB**：并排盲评里，测试结果被偏好于基线的比例。GSB $+x\%$ 表示有 $x\%$ 的测试页优于基线。

在线实验在淘宝跑了四周以上，分到 10% 长尾查询流量。目标是查询–商品相关性，论文称订单量没有被伤害。

## 离线：同一 200M 规模，只差有没有合成数据

表 1 两边都是 Tbstars-3B、200M 训练规模。基线没有针对长尾的合成数据。

| 类型 | Item Goodrate | Query Goodrate@10 | Query Goodrate@100 |
| --- | --- | --- | --- |
| Q&A | 81.85% → 87.19%（+5.34pt） | 96.31% → 97.74%（+1.43pt） | 87.73% → 91.36%（+3.63pt） |
| Alternative | 23.45% → 30.08%（+6.63pt） | 53.43% → 60.73%（+7.30pt） | 21.57% → 28.00%（+6.43pt） |
| Negative | 48.58% → 61.53%（+12.95pt） | 83.43% → 88.88%（+5.54pt） | 51.01% → 64.16%（+13.15pt） |
| Knowledge | 60.58% → 71.31%（+10.73pt） | 84.61% → 89.74%（+5.13pt） | 64.60% → 74.20%（+9.60pt） |

Item Goodrate 抬得最多的是否定类和知识类。否定类对普通语义匹配很难：「非木质衣柜」仍会召回木质衣柜。知识类里很多是穿搭，例如「蓝裙子配什么外套」，基线常召回蓝色外套，只是部分相关。

表 2 是合成对本身的人工准确率：每类抽 1000 对。

| | Q&A | Alternative | Negative | Knowledge |
| --- | ---: | ---: | ---: | ---: |
| Accuracy | 90.6% | 64.5% | 81.6% | 86.0% |

三类超过 80%，问答超过 90%。平价替代只有 64.5%，和表 1 里 Alternative 的绝对 Item Goodrate 仍然只有 30% 是同一件事：这类要强领域知识和时效信息，改写模型的参数知识供不上。

## 在线 SBS

实验组是训练里加入合成数据的检索，不是线上改写。

| 类型 | Item Goodrate | Query Goodrate | GSB |
| --- | ---: | ---: | ---: |
| Q&A | +5.12pt | +7.45pt | +19.71% |
| Alternative | +5.00pt | +8.62pt | +27.66% |
| Negative | +6.97pt | +7.65pt | +31.59% |
| Knowledge | +2.58pt | +5.82pt | +15.66% |

Item Goodrate 最大增益在否定类（+6.97pt）。Query Goodrate 最大增益在平价替代类（+8.62pt），这也是摘要里「最高 8.62pt」的那一格。论文说这两类表达模式比较整齐、意图细，传统检索因语义复杂处理不好，所以合成对的边际更大。

## 局限

框架只有文本知识，处理不了依赖图像的需求，例如「同款衣服」。平价替代类检索有提升，绝对水平仍然差，只靠改写模型里的参数知识不够。

方法上可以单独记住的四点：监督必须落在原始查询–商品对上；三路奖励里 PDA 管的是商品语言而不是用户问句；业务相关性模型会把词面重叠当成相关，所以要通用模型再滤一次；改写器留在离线，避免延迟和改写不稳定进到线上。

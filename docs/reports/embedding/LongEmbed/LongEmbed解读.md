# LongEmbed 补充解读：能输入、能注意、能保留是三回事

> 以下是对长文向量系统的实践分析。

## 三个不同的瓶颈

输入层能接收长文本，只说明没有截断或位置越界。注意力能跨远距离传播，说明网络可能使用远处信息。最终一个固定维度向量能为未来各种查询保留所有细节，则是更强的要求。

扩窗主要处理前两个条件，不能自动解决第三个。把一本书压成一个向量，即使每个 token 都参与计算，也可能让小人物、日期或否定细节在池化中被主线主题盖过。

## 与分块、Late Chunking、多向量的关系

PCW 先独立编码块再平均，缺少块间交互；Late Chunking 先让长上下文参与编码，再对不同片段池化；多向量表示则保留多个 token/patch 向量，推迟聚合到查询时。它们在上下文利用和保存粒度上做了不同选择。

因此不能只比较“最大 token 数”。同样 8k 输入，最后保留 1 个向量、几十个块向量或几千个 token 向量，存储、召回粒度和细节保真度都不同。

## 为什么 BM25 对照特别有价值

若目标包含独特人名、编号或口令，词项索引可以直接定位；一个强语义向量却可能把它当低权重细节。LongEmbed 附录提醒我们：长上下文宣传并不能免除精确匹配基线。

业务评测应将“概括主题”“定位一个事实”“跨段综合”分开，检查目标在开头、中间、末尾时的召回变化。对于精确实体，保留 lexical/hybrid 通道往往值得验证。

## 扩窗与 YaRN 如何衔接阅读

先看 RoPE 相位为什么超出训练范围，再看 PI、NTK-aware、SelfExtend 各自如何改变局部与远距位置关系；之后读 YaRN 的分频段处理与 attention scaling。LongEmbed 提供的额外视角是：生成模型上的长文能力收益，最终还必须转换成 embedding 检索指标才算成立。

## 一个合理的落地比较

同一模型分别测试截断、独立分块、扩窗单向量和上下文感知分块；保持检索候选预算和下游重排器一致。除 Recall/nDCG 外，记录文档编码时间、索引字节数和证据定位准确率。若只比较模型支持长度，容易把计算量增长误当成有效能力增长。

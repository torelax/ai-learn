# CLIP 补充解读：开放类别不等于开放式理解

> 本页解释 CLIP 的任务接口、打分和迁移边界。

## 分类头来自文字

传统分类头为每个类别存一行可训练权重，CLIP 用文本塔临时生成这些权重。它因此能换标签集合，但仍是在给定候选中比较相似度。把候选从“猫/狗”改成“猫/狗/玩具猫”，预测和 softmax 概率都会改变；分数不是脱离候选集合的事实置信度。

## 图文匹配为何没有自动带来强文本检索

训练只要求图像与描述对齐，不要求问题与答案、论点与反驳在文本空间中具有正确距离。Jina-CLIP 增加文文监督正是补这一缺口。词面相似的两段描述可能都符合一张图，但不一定互为答案。

## 全局语义与局部关系

“红车在蓝车左边”和“蓝车在红车左边”包含相同对象，整图对比目标可能只抓主要概念。后续局部定位、生成监督、patch 自蒸馏以及多向量检索，分别从训练信号和匹配粒度补充信息。它们并不是简单替换一个 softmax 就能解释的进展。

## 正确解读效率与鲁棒性

原论文的零样本、少样本线性探测、全监督线性探测是三个不同协议。模型是否微调、用多少目标标签、提示是否经过验证集选择，都影响比较。鲁棒性结果也应该作为目标分布验证的理由，而不是不做微调的普遍规则。

对实际检索，可把 CLIP 当作语义基线，再分别测试细节、关系、OCR、多语言及目标领域。若只在自然图图文配对上测试，容易高估它对业务文档的覆盖。

# GME 补充解读

本文讨论原论文之外的实现与选型含义；论文方法与实验见 [GME 详解](GME详解.md)。

## 一个向量空间不等于一种相关性

图片相似、文档回答问题、图文组合提供证据是不同的关系。GME 的价值在于把这些关系共同训练进一个模型，工程上可以减少维护多个编码器的成本。但查询指令变化后，旧候选向量是否仍适配，要由训练时的候选格式决定。不能任意改写候选模板后沿用旧索引。

## 为什么合成时要隐去实体名

“鸢尾原产哪里”用文本检索便能解答；“图中这株植物原产哪里”才要求识别图像。把实体名替换为指代是一种数据约束：让查询的信息分布迫使模型利用视觉输入。实际构造样本时还应比较去图、换图、只保留文字三种结果。如果去掉图片几乎不掉分，数据可能仍存在文本捷径。这是从论文流程推导的诊断方法，并非论文已报告的全部实验。

## 与多向量视觉文档检索如何取舍

GME 每个对象输出一个向量，易接入普通 ANN；ColPali/ColQwen 保留多个页面局部向量，适合依赖表格单元格、局部文字或图形细节的相关性。单向量更省存储并不意味着总成本必然更低：高分辨率 VLM 编码仍可能昂贵。比较时应同时测离线建库、在线查询、索引大小和同一候选库上的召回。

对需要细粒度页面证据的系统，可用 GME 召回再交给多向量或交叉编码器重排。但第二阶段救不回第一阶段未召回的页面，应该先测 Recall@K 再评估重排收益。

## 如何理解训练消融

LoRA rank=8 优于全参的结果说明这套数据和预算下，适度约束参数更新有效；它没有证明低 rank 拥有更强的表示上限。全参可能需要不同学习率与训练时长。类似地，mean pooling 和双向注意力没有胜出，也不能移植成所有 decoder embedding 的通则。

UMRB 总分混合不同指标且按数据集平均。业务如果以长页面或组合查询为主，应优先看对应子集，并检查训练数据和测试域之间的关系。总榜分数适合观察覆盖面，不能直接预测业务收益。

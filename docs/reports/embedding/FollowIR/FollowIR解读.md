# FollowIR 补充解读：相关性是条件化的

> 本页是对评测和系统设计的进一步分析。

## 同一句话，相关性可以改变

查询“新能源汽车电池回收”，条件 A 要政策综述，条件 B 只要实际回收工艺并排除政策。两个任务可能使用几乎相同关键词，却要求不同排序。若 embedding 只编码主题，A、B 的向量可能很近；一个把否定后面的“政策”继续当正关键词的模型甚至会朝相反方向移动。

“Retrieve relevant passages”主要指定任务类型，不能代替这些逐查询变化的约束。这正是 FollowIR 比传统 BEIR 总分多测到的一层能力。

## p-MRR 的直觉和盲区

一个被新条件排除的文档从第 1 降到第 4，得 $1-1/4=0.75$；从第 4 升到第 1，得 $1/4-1=-0.75$。它奖励该降的文档下降。

但假如模型把所有文档都排坏了，部分被排除文档也可能碰巧下降。因此 p-MRR 必须和 MAP/nDCG 一起看。其单文档形式依赖排名比值，1→2 与 50→100 都得 0.5；它不是绝对 reciprocal-rank 差，理解时不要简单说“越靠前的同倍变化一定权重越大”。

## 与 NLI 的联系

NLI 检查前提是否蕴含假设；条件检索判断文档是否满足需求。可以把部分需求转成待验证主张，让 cross-encoder 判断，但两者不能直接等同。例如“只要 2024 年以后的实验论文”同时涉及时间、文档类型与研究内容，需要多个证据字段。

自然语言排除条件若非常重要，可以将可结构化部分做 metadata filter，再用指令感知 reranker 处理语义条件。这样仍需要检查漏召回：后面的精排器无法找回第一阶段已经丢掉的文档。

## 怎样给自己的系统补这种测试

从真实查询挑出限定条件，成对构造“只改变一个要求”的需求；人工标记哪些文档应该升、哪些应该降。同时记录候选召回、满足条件的比例与最终排序质量。重点覆盖否定、时间、实体、比较对象和多条件合取，而不只是把 prompt 改写成不同说法。

这些是借鉴论文的评测建议，不代表 FollowIR 原数据覆盖了所有这些场景。

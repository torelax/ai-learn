# Jina-CLIP v2 补充解读：三个成本旋钮

> 本页补充讨论分辨率、维数与任务配比，不将它们混成“模型越大越好”。

## 分辨率影响读到什么，维数影响存下什么

页面缩成 224² 时，小字与表格边界可能已经消失，再增加输出维数也找不回来。把图片提高到 512² 主要改善输入信息保留；MRL 把输出从 1024 截到 256 主要节约索引与点积成本。两者作用位置不同，不能互相替代。

对一个固定 checkpoint，截短向量通常不会省掉前面的 Transformer 编码。若瓶颈在离线处理海量高分辨率图片，MRL 只改善后半段成本；若瓶颈是向量库内存，它才更直接。

## 单向量与多向量的区别仍然存在

v2 看更多 patch，但最终只存一个向量。ColPali 则保留大量 patch 向量，让查询在检索时选择局部证据。前者索引简单，后者更容易表达不同查询关注页面不同区域的需求。ViDoRe 的提升证明高分辨率和数据有帮助，却没有消除这项结构差异。

## 多语数据的收益也有对照范围

相对英语 v1，多语提高很大是预期现象；更有辨识力的是与 NLLB-SigLIP 和专用 Jina v3 的比较。前者检验图文多语对齐，后者检验文本能力的机会成本。最好的模型取决于系统究竟需要哪几类查询。

## 共同温度为何可能不合适

一张图可包含多个合理描述，文本问答又可能要求精确回答。同一个余弦差值不一定具有相同的监督意义。共同温度把两类负例惩罚绑定，可能让某一任务过强或过弱。论文的失败实验提醒我们：简化目标的形式，不等于简化优化问题。

实际评测可分别观察图文双向、纯文本检索、STS、文档页和混合候选，最后再按业务权重汇总。用一个总分掩盖这些方向，容易看不到最后一阶段的真实取舍。

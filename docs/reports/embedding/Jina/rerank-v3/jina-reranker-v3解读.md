# Jina-reranker-v3 补充解读

> 本页区分论文结果与进一步的理解、工程取舍。

## Last 与 Late 是两条轴

Late 指查询和文档何时发生交互，Last 指在哪个位置读出。LBNL 在 Transformer 内已经发生交互，所以它的文档向量依赖查询和前文候选，无法像 ColBERT 一样作为全库稳定索引直接缓存。

## 因果上下文不能双向互看

后面的文档能读取前面的文档，反方向不行；末尾查询能看到整个前缀。调换候选顺序会改变可见信息，因此顺序消融既是排序稳健性实验，也是架构依赖性的体现。平均分变化较小也不能保证每条查询不敏感。

## 候选批次会改变比较范围

受上下文限制分批后，来自不同批的文档不能在同一次前向里比较。跨批分数是否可比需要看具体实现、查询读出和校准策略。不能把论文表中的 131K 骨干窗口、8K 有效训练序列、64 篇分批与评测 top-100 当作同一种长度指标。

## 重排并非必然改进

论文 CoIR 的初始检索分数 73.94，v3 重排后 70.64。领域不匹配或列表监督偏好可能打乱原有正确顺序。部署时应保留不重排基线，必要时按领域路由，而非假设增加一阶段总会更强。

# Jina Embeddings v1 补充解读：数据量的三个口径

> 本页补充分析数据筛选与语义边界，不把工程推论当作原论文结论。

## 数据池、采样量与有效监督不是同一个数

16 亿原始对、3.85 亿过滤后数据、1.8 亿实际采样，回答的是三个问题。复现时仅写“用 3.85 亿对训练”会掩盖数据权重、重复和覆盖率。更有用的记录是每个源保留多少、被抽到多少次、承担什么任务关系。

按来源组 batch 让负例更接近真实任务：若把医学问答和购物标题混在一起，模型可能靠领域差异就分开负例；同源 batch 则迫使模型比较更相近的候选。但同源也更容易有多个真实正例，数据池越大越需注意假负例。

## 一致性过滤是一种教师选择

MiniLM 判断“这是不是合理配对”，等于把它的检索偏好作为数据入口。容易匹配的近义、显式答案会被保留，需要推理或跨语言理解的难样本可能被丢掉。工程上应同时检查被过滤掉的样本，尤其是专有名词、否定和长距离关系，避免把教师能力边界变成训练集边界。

## 否定不是一个通用的拉远规则

对于“相同意思”任务，肯定与否定通常应该拉远；对于“查找关于某个说法的证据”任务，反驳文档可能恰好相关。本文的否定数据改善的是它所定义的语义区分，不意味着所有检索都应排除反驳材料。判断 embedding 是否“懂否定”前，先写清相关性定义。

## 为什么要同时使用两类排序损失

InfoNCE 让正例在 batch 内胜出；margin 项要求本条正负拉开明确距离。前者依赖负例池，后者依赖给定三元组。二者可能互补，但若负例标错，margin 会持续放大错误，因此论文先用 cross-encoder 去噪有明确因果位置。

从后续 Jina v2/v3 回看，v1 值得学的是数据流程，而非今天仍应选择哪个旧模型。长上下文、多语言、任务适配器属于后续工作的增量，不能反向写进 v1 的能力描述。

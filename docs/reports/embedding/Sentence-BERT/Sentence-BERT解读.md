# Sentence-BERT 补充解读：训练关系，部署向量

> 以下是结合论文的机制解释与实践推导；论文结果和完整实验结构见主阅读笔记。

## NLI 到底怎样帮到句向量

NLI 输入“前提”和“假设”，标签是蕴含、矛盾或中立。例如“有人正在弹钢琴”与“有人在演奏乐器”可构成蕴含关系；“没有人在演奏”则可能构成矛盾。它让模型关注主体、动作、否定等句级语义。

SBERT 的 NLI 头接收两个独立编码后的向量及其绝对差，所以分类器若要正确判断，编码器必须把这些关系所需信息装进各自向量。梯度由分类头流向两个共享分支，最终获得较适合余弦比较的表示。

不过三分类损失**没有直接规定**“蕴含余弦必须等于 1、矛盾必须等于 −1”。一个矛盾句对常常仍谈论同一个主题；逻辑关系、释义相似与搜索相关性并不等价。原论文的成功是实验结论，不是由分类公式自动推出的几何定理。

## 与 NLI 交叉编码器的区别

| 形式 | 两句何时交互 | 输出与适用任务 |
|---|---|---|
| SBERT + NLI 训练头 | 各句经过 Transformer 后，向量在浅层头相遇 | 学习可缓存句向量 |
| NLI cross-encoder | 从 Transformer 注意力层就联合处理 | 针对这一句对判断蕴含／矛盾 |
| SBERT 推理 | 编码器完全独立，最后余弦比较 | 大语料召回、相似句、聚类 |

所以“基于 NLI”说的是监督任务，“双塔／交叉编码器”说的是结构。二者不是同一级分类。若要核验某条证据是否支持一项具体主张，NLI 交叉编码器可做精细判断；若要先从百万条材料找到候选，独立句向量更合适。

## 为什么 padding mask 不是小细节

假设句子只有 10 个有效 token，却被 pad 到 128。如果简单把所有位置输出平均，表示会随着同 batch 其他句子的长度而变化。正确 mean pooling 按 attention mask 加权；归一化后使用内积可等价于余弦。对不同模型还要遵守其特殊 token 与池化约定，不能只看到“BERT”就统一取 CLS。

## 今天怎样使用这篇论文

Sentence Transformers 是软件框架，SBERT 是这篇论文提出的方法，某个 Hugging Face checkpoint 则是具体训练产物。框架支持的现代模型可能使用 MNRL、蒸馏、长上下文、多语言等流程；不能把全部都描述为“SNLI + MultiNLI 三分类”。

对于检索项目，先明确 query–document 是否对称。如果是“两个问法是否同义”，原论文的句子相似度范式很自然；如果是“问题对应包含答案的长段落”，应使用检索数据训练的模型，并分别验证召回和排序。高 STS 分数不保证包含答案的文档一定排在前面。

## 小实验能验证什么

可以固定同一个骨干，比较未经微调的 mean pooling、NLI 微调和 query–passage 对比微调。保持分词、长度上限与归一化一致，同时测 STS、真实检索 Recall@k 和否定／实体交换例子。这样能看到训练任务在改变什么，避免把池化方式或模型规模当作唯一原因。

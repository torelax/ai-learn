# InPars-v2：开放查询生成器与相关性过滤

> **简述**：用开源 GPT-J 生成查询，再由 monoT5 按查询–文档相关性筛选训练对，改进 InPars 的可复现性与领域适配效果。
>
> **论文**：[InPars-v2: Large Language Models as Efficient Dataset Generators for Information Retrieval](https://arxiv.org/abs/2301.01820v4) · Jeronymo 等 · 2023-01 首发，本文据 2023-05 的 v4。
>
> **核心组件**：GPT-J 6B 生成，MS MARCO monoT5-3B 过滤与继续训练，BM25 召回。[作者代码、数据与模型](https://github.com/zetaalphavector/InPars/tree/master/legacy/inpars-v2)

## 论文简介

InPars 已证明，少量示范可以引导大语言模型从目标语料生成查询，再用合成数据训练检索模型；但依赖闭源生成器，且生成概率不直接衡量相关性。InPars-v2 将生成器替换为开放的 GPT-J 6B，并用已有的 MS MARCO monoT5-3B 为查询–文档对打分，保留最高分样本，再训练域内重排器。论文在 BEIR 的 18 个数据集上分别训练模型，平均 nDCG@10 从仅用 MS MARCO 的 0.533、加 v1 数据的 0.539 提高到 0.545。方法公开了代码、数据与权重，但仍依赖监督重排器，统一提示在论点检索上也未能超过 BM25。

## 摘要

本文将大语言模型作为检索数据集生成器，延续“少样本提示 → 文档生成查询 → 训练检索模型”的路线。相较依赖 GPT-3 的 InPars 与依赖专有 FLAN 的 Promptagator，InPars-v2 采用**开放权重的查询生成器**，并借助已有强重排器挑选更可靠的合成正例。

在本文配置下，BM25 加经过合成数据继续微调的 monoT5，在 BEIR 全量平均上取得当时具有竞争力的结果。作者同时发布代码、合成数据和微调权重，使整条流水线可供后续复现与改进。

## 引言与背景

**领域训练数据稀缺**是检索模型部署中的常见问题。InPars-v1 从语料文档生成相关查询，将大模型的使用移到离线阶段：用少量 MS MARCO 示范构造查询–文档正例，再训练重排器。

Promptagator 采用相似的数据合成思路，但引入数据集专用提示、更大的生成模型，以及由较小模型组成的可训练检索与重排流水线。InPars-v2 则保留 v1 的总体架构，集中改变两个环节：

- **查询生成**：用 GPT-J 6B 替换专有的 OpenAI Curie。
- **样本筛选**：用 monoT5 的相关性分数替换生成器给出的查询对数概率。

本文实验仍以 **BM25 + 交叉编码器重排**为最终系统，没有训练新的稠密召回器。

## 方法

### 使用 GPT-J 生成查询

对 BEIR 的每个数据集，从其语料中随机抽取 **100,000 篇文档**。每篇文档输入 GPT-J 6B，生成一条查询；若语料不足 100,000 篇，则按语料实际文档数生成。

提示沿用前作的 **GBQ（Guided by Bad Questions）**，包含 **3 组 MS MARCO 示例**，解码使用贪心策略。GBQ 通过好、坏问题的对照，引导模型生成更贴合文档上下文的查询；本文没有为各数据集另行定制提示。

在一块 A100 上，生成 100,000 条查询平均需要约 **30 小时**。开放生成器使生成步骤不再依赖商业 API，但这一阶段仍是主要计算开销。

### 按相关性筛选正例

v1 根据“给定示范和文档，生成该查询的对数概率”筛选样本。v2 改用已在 **MS MARCO 上微调一个 epoch 的 monoT5-3B**，直接估计每个查询–源文档对的相关性。

具体过程是：给全部生成对打分，保留**最高的 10,000 对**，作为训练正例。论文使用的起点为 [`castorini/monot5-3b-msmarco-10k`](https://huggingface.co/castorini/monot5-3b-msmarco-10k)。在 TPU v3-8 上为 100,000 对打分约需 **1.5 小时**；作者估计在 A100 上约需两倍时间。

这里的监督来源需要明确：目标语料的查询与相关性标签由合成流程构造，但**过滤器本身经过 MS MARCO 人工标注训练**，不能将整条训练路线描述成完全没有监督信息。

### 构造负例并微调重排器

对每条保留的合成查询，以 BM25 召回 **top-1,000 文档**，随机选一篇作为负例。最终训练集包含 **10,000 个正对和 10,000 个负对**。

最终重排器同样从 MS MARCO 上训练了一个 epoch 的 monoT5-3B 出发，再在该目标集合的合成数据上训练一个 epoch。过滤与重排训练使用相同类型的预训练起点，过滤完成后才进行目标语料的继续微调。

```mermaid
flowchart LR
    A["目标语料文档"] --> B["GPT-J：3-shot GBQ 生成查询"]
    B --> C["MS MARCO monoT5：相关性过滤"]
    C --> D["保留 1 万正对"]
    D --> E["BM25 top-1000 随机取负例"]
    E --> F["monoT5 在合成数据上继续微调"]
    F --> G["线上：BM25 召回 + 域内 monoT5 重排"]
```

图按论文方法节整理。GPT-J 只参与离线生成；monoT5 先用于数据筛选，再经继续训练成为线上重排器。每个 BEIR 数据集独立执行这条流程。

## 实验设置

### 训练与评测配置

| 项目 | 论文设置 |
| --- | --- |
| 生成器 | GPT-J 6B，3-shot GBQ，贪心解码 |
| 过滤器 | monoT5-3B，已在 MS MARCO 上训练 1 epoch |
| 每集合训练数据 | top-10,000 正对 + 10,000 个 BM25 负对 |
| 重排器起点 | MS MARCO monoT5-3B，继续训练 1 epoch |
| 优化器与学习率 | Adafactor，恒定 $10^{-3}$ |
| Batch | 64 正对 + 64 负对 |
| 训练规模 | 18 个数据集分别得到 18 份重排器 |
| 微调耗时 | 每份合成数据在 TPU v3-8 上不到 10 分钟 |
| 首阶段检索 | Pyserini flat 索引，BM25 默认 $k_1=0.9,b=0.4$，top-1,000 |
| 指标 | 在对应测试集上计算 nDCG@10 |

**BEIR** 是异构检索基准，覆盖科学与医学检索、问答、事实核查、新闻检索、重复问题及论点检索等任务。相同的合成问题风格不一定适用于所有任务；例如 NQ 侧重寻找能回答问题的段落，而 ArguAna 要寻找反论点，相关性标准不同。

### 比较方法

论文比较 BM25、只在 MS MARCO 上训练的 monoT5-3B，以及继续用 InPars-v1 或 v2 合成数据训练的模型。另列出 Promptagator 与 RankT5 的公开结果；RankT5 是采用排序损失的 T5 排序模型，论文当时未获得其公开代码和检查点。

表中 **MARCO、+InPars-v1、+InPars-v2 共用监督训练起点**；它们比较的是是否加入目标集合的合成训练，以及合成流程的差别。

### 与 Promptagator、RankT5 的比较

在 Promptagator 报告的共同子集上，v2 平均为 **0.533**，Promptagator 为 **0.531**，RankT5 为 **0.536**。因此，全量平均与共同子集平均需要分别阅读；表格没有提供另两种方法完整 18 集合的平均。

**论点检索是明显的弱项**：ArguAna 上 BM25 为 0.397，v2 为 0.369；Touche 上 BM25 为 0.442，v2 为 0.291。Promptagator 在 ArguAna 达到 0.630，RankT5 在 Touche 达到 0.486。作者将这类差异与数据集专用提示联系起来：论点检索不同于一般问答式查询，可能需要不同的生成任务描述。

论文脚注报告，在 ArguAna 上改用数据集专用提示，初步实验可提升超过 **10 个 nDCG@10 点**，但没有在本文给出完整配置与全 BEIR 结果。主表仍对应统一 GBQ 提示。

## 结论

InPars-v2 的贡献是把查询生成与数据筛选分别交给开放大模型和强重排器，在可复现的流程中改进领域合成训练数据。与只做 MS MARCO 监督训练或再加入 v1 数据相比，v2 的全量 BEIR 平均更高；作者也公开了合成数据和微调模型。

本文是一篇短报告，没有单独消融“仅换 GPT-J”与“仅换过滤器”的贡献。结论应落在整套新流程的效果上；每个集合独立训练、已有监督过滤器和统一提示的任务适用范围，仍是理解其结果的重要条件。

# VLM2Vec 补充解读

论文精炼版见 [VLM2Vec 详解](VLM2Vec详解.md)。以下进一步解释评测与训练选择。

## 生成能力如何转成表示能力

VLM 预训练使隐藏状态能够融合图文信息，但生成损失并不保证两个独立输入的向量距离适合检索。对比训练提供这种几何约束。EOS 是一个可访问前文的汇聚位置，真正决定表示质量的仍是训练目标、数据和读出方式的匹配，而非 EOS 本身具有什么神奇属性。

## 指令有效，不等于逻辑约束已经可靠

VLM2Vec 的任务指令告诉模型是识别类别、回答问题还是寻找修改后的图片。FollowIR 则进一步检验改变相关性条件后排序是否跟着变化。一个模型可能对任务模板有较强适应，却仍忽略“排除某类”“必须满足时间条件”等细粒度约束。业务上应构造内容相同、仅约束不同的查询对，观察排序变化。

## GradCache 该怎样理解

它让一个对比损失看到完整大批次，同时把编码器激活拆开存放。实现时两次前向必须保持一致：dropout 的随机状态、数据增广和图像裁剪都需要控制，否则缓存表示对应的梯度与重算图不一致。只增大梯度累积步数，损失仍只看微批次中的负例，不能替代这一过程。

## 如何读取 62.9 这个分数

这个数字属于论文 v3 的高分辨率 LLaVA 配置，不能与较早报告的低分辨率 55.0 混写。评测中的 VQA 是候选答案检索，grounding 是候选区域选择；如果产品要求生成答案或从整图检测区域，还需要额外模块与评测。

候选规模实验更接近真实系统风险。先在固定大候选库验证 Recall@K，再评估模型索引近似带来的损失，才能把“表示能区分”与“系统能找回”分开。比较 CLIP 和 VLM2Vec 时，还应记录图像 token 数、编码吞吐和峰值显存，避免只看分数忽略成本。

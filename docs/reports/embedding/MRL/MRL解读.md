# MRL 补充解读：截短为什么必须先学会

> 以下是几何直觉和部署推导，原论文评测以视觉与跨模态任务为主。

## 普通向量截断为什么没有保证

假设语义信息均匀分散在 768 个坐标，只取前 64 维可能丢掉重要方向。即使完整向量的余弦很好，也没有目标要求前 64 维保持同样的邻居关系。MRL 在训练中显式加入这些前缀目标，让模型重新安排信息。

但它不是 PCA：没有要求坐标按方差排序或彼此正交。也不是多条独立 embedding 拼起来：短表示是长表示的严格前缀，各尺度共享前面的坐标。

## 截断后重新归一化

若完整 $z$ 已单位归一化，$z_{1:m}$ 的范数通常小于 1，而且不同样本剩下的范数不同。直接做截断内积会同时受到前缀长度和范数影响。使用余弦时，应计算 $z_{1:m}/\|z_{1:m}\|_2$；query 和 document 要使用相同维度及归一化约定。

## 节省的究竟是哪部分成本

固定用短向量建库，可以减少向量数据存储和距离计算，但编码器通常仍生成完整隐藏状态。两阶段方案为粗召回保存短向量、为精排保留完整向量，主要节省高频扫描和索引成本，不一定同比节省全部磁盘。

假设百万文档、float32、从 1024 截到 128 维，裸向量由约 4.096GB 降至 0.512GB；这是纯数组估算，不包含 HNSW 图、ID、metadata 与副本。如果另存全维用于重排，则全维存储仍在。

## 召回上限比精排维度更重要

先用 64 维取 100 候选，再用 1024 维精排，最终效果受这 100 个候选的召回限制。低维如果把一个关键但细微的相关文档排到第 500，高维阶段看不到它。应联合扫描“前缀维度 × 候选数”，而不是固定 top-k 后只观察重排分数。

## 与量化和多向量压缩的区别

MRL 减少每个向量的维度；int8/binary 减少每个维度的位数；token compression 减少每篇文档的向量数量。三个轴可以组合，但误差也会叠加。特别是 late interaction，短前缀可能改变每个 query token 的最匹配位置，需按完整 MaxSim 检索指标验证。

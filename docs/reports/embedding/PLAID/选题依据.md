## 为什么补 PLAID

规划将 `LateInteraction与ColBERT到ColPali.md` 列为 P1，明确要解释 MaxSim、ColBERTv2/PLAID 压缩与页级多向量；Phase D 的相关专题仍未勾选。资料清单的 PLAID 条目标为“ColBERT 索引/检索工程加速（工程必读）”，推荐顺序为 ColBERT → ColBERTv2 → PLAID。

实际文件检查发现，ColBERT 与 ColBERTv2 已有独立深读、PDF 和图片；PLAID 在相关报告中主要是导读引用，本次开始前未找到其独立目录、PDF、中译或专篇。这里的“未完成”指缺少这些深读产出，并不把已有 mentions 当作零研究。

PLAID 的价值是补齐“模型表示准确 → 压缩存储 → 低延迟全库检索”的链路。它不是再训练一个更大的 embedding 模型，而是在 ColBERTv2 的质心与残差表示上安排低成本筛选和昂贵精排的先后次序。既能解释多向量的上线成本，也能给后续视觉页检索提供可验证的迁移问题。

相较之下，CLIP、SigLIP、GME、VLM2Vec 已有深读或合写；SPLADE 属于规划 P2。PLAID 对 P1 路线的边际补充更直接。

## 核心问题与大纲

读者前提：已了解 ColBERT 的 MaxSim 和 ColBERTv2 的质心＋量化残差表示。  
读完收获：能解释四阶段候选筛选、区分近似质心分数与最终残差解压分数、正确理解速度与质量口径。  
挂接主文：表示范式、Pipeline 工程、视觉文档多向量检索与向量部署章节；不另建平行总论。

- 动机：到底是 query 编码、候选生成、索引读取、解压还是 MaxSim 在耗时？
- 算法：质心交互为什么能做高召回筛选？质心剪枝按哪个维度取最大值？
- 系统：为什么倒排表改存 passage ID，为什么尽量延迟加载残差？
- 实验：Figure 3 的 recall 相对于 baseline top-k 还是相关性标签？“最高 45×”基于哪一档硬件、候选深度和质量指标？
- 边界：质心分数不是保守上界，全文“无质量损失”不能代替逐指标检查；文本结果不能直接证明图像 patch 迁移有效。

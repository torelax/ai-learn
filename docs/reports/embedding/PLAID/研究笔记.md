## 公式与单位核查

- 原式 (1)：每个 query token 沿 passage 轴 max，再沿 query 轴 sum；通常非对称。
- 原式 (2)：C 为 K×h，Q 为 m×h，CQᵀ 为 K×m。
- 原式 (3)/(4)：PDF 与 HTML 都保留原作的轴方向疑点；不是 HTML 转换造成的误差。规范化后 B 为 n×m，分数应 sum_i max_j B[j,i]。
- 原式 (5)：沿 query 轴取 max 后与阈值作 ≥ 比较；通过筛选的是完整质心行。
- §3.1 的质心 ID 是 4 bytes，§3.2 写 4-bit；译稿保留原句并加注，不把后者带进存储估算。
- “完整重建”是对量化表示解压；不能称为原始未压缩 embedding 的精确恢复。

`check_formulas.py` 从固定官方 `colbert.py` 里取出原始纯 Python `colbert_score` 与 `colbert_score_reduce` 执行，不导入整个 ColBERT 训练/索引引擎。8 项检查实际通过：MaxSim 轴方向、负值/padding、非对称性、质心 gather 形状、重复质心不变性、阈值边界、非上界反例、论文倍率与百分点算术。这个执行范围不能冒充编译 C++/CUDA 内核或 benchmark 复现。

## 数字阅读纠错

MS MARCO v1 的最保守档，GPU 259.6/38.4≈6.76×；8线程 CPU 4568.5/101.3≈45.10×。R@1000 为 98.3→97.5，下降 0.8 个百分点；v2 为 88.1→85.7，下降 2.4 个百分点。v2 的 k=100 还存在 MRR@100 18.0→17.9、R@100 68.2→67.0 的轻微下降。作者整体“不掉质量”的描述不能替代逐指标核查。

Figure 6 的 42.4× 来自 500 个随机查询，Table 3 的 45× 来自完整查询集；Figure 2 分解图有 query 编码阶段，而结果表的计时排除了编码。GPU 实验可用全部 56 CPU 线程，CPU 则为 1 或 8 线程。不同基线、不同深度、不同采样和不同计时口径不能混合算加速。

# Qwen3-VL-Embedding 补充解读

论文内容见 [Qwen3-VL-Embedding 详解](Qwen3-VL-Embedding详解.md)。

## 单向量与 ColQwen 的差别

Qwen3-VL-Embedding 用一个向量概括输入，能直接接常规向量索引；ColQwen 保存多个 token/patch 向量并用 MaxSim 汇总局部匹配。二者可能共享 Qwen 视觉语言骨干，但索引、打分与存储结构不同。图表小字或多实体关系是否被单向量压缩丢失，需要通过目标任务验证。

## 蒸馏为何会让总分下降

Reranker 提供的是检索相关性监督，并不自动保留所有分类或问答能力。s2 在检索上更强但综合分数低于 s1，体现多任务目标间的取舍。合并是在参数空间中折中两个状态，不能理解成推理时运行两个模型投票。合并比例应在代表性任务上选，而不能只优化一个检索集合。

## MRL 和 QAT 压缩不同维度

MRL 减少每个向量的元素数量；QAT 减少每个元素的位数。仅计算原始向量，4,096 维 float32 约 16 KiB，512 维 int8 约 512 B，相差 32 倍；实际索引还有图结构、元数据和量化参数开销。二者组合后是否保住召回，需要直接测相同候选库，而不能把各自单独的掉分简单相加。

## 视频预算的三个旋钮

帧数决定时间采样密度，单帧分辨率决定空间细节，总 token 决定模型实际负担。短暂动作可能需要更多帧，屏幕文字可能需要更高分辨率。在固定预算下，两者相互挤占。先判断任务需要时间还是空间细节，再配置抽帧和缩放，比统一拉满更合理。

## 重排的接入方式

先用向量模型召回足够候选，再对每个 query–document 对计算 yes/no 分数。这个分数适合排序，但并未自动校准成跨任务通用概率。若要设置拒答阈值，应在自己的正负样本分布上校准；否则不同任务指令和候选难度可能导致阈值失效。

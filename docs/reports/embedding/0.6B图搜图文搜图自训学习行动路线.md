# 0.6B 以下 · 图搜图 / 文搜图自训学习行动路线

> 目标不是「选现成模型去用」，而是围绕任务自建数据、训练（含大模型蒸馏）出 ≤0.6B 的部署模型 · 学习规划 + 行动清单

> **任务**：`图搜图`（image→image）与 `文搜图`（text→image）。
> **部署约束**：上线模型**单个**参数量 ≤ **0.6B**（不是两模之和）。
> **做法**：以自有 / 合成任务数据训练为主；允许用更大教师模型做蒸馏、伪标签、硬负例挖掘——
> **蒸馏不是偷懒选型，而是把算力花在训练侧、把体积留给推理侧**。
> 本文是**学习规划与行动路线**：先建立正确问题分解，再按周推进数据、损失、蒸馏、评测与迭代。
> 不替代《图文 Embedding 模型技术综述》；技术背景以该文为参照，本文只管「你要亲自训出什么」。

## 一、问题正确定义

#### 图搜图要解决什么

*image → image · 同模态*

查询是一张图，库里也是图。你要先定义「相似」是**实例级**（同款、近重复、同一物体） 还是**语义级**（同类别、同场景）。定义不同，标签、损失、教师全变。

- 实例相似：往往受益于视觉自监督表征 + 度量学习
- 语义相似：更接近 CLIP 图像塔 / 分类语义空间

#### 文搜图要解决什么

*text → image · 跨模态*

查询是文本，库是图。必须把文与图映到**同一向量空间**（或可比较的空间）。 这不是「再训一个文本 embedding」能单独完成的。

- 训练单元：图文对（或 hard negative 三元组）
- 核心损失：对比学习（InfoNCE / Sigmoid / CLIP 式）

> **说明**：**两个任务可以共用一个双塔学生，也可以训练两个学生。** 约束是「每个上线模型 ≤0.6B」。 若合并为一个双塔：总参 ≤0.6B，同时服务文搜图，并用图像塔兼做图搜图（或再加轻度图像对比头）。 若拆成两个模型：每个 ≤0.6B，图搜图专精视觉、文搜图专精对齐——通常更容易把各自指标打高。 **这是架构决策，第 1 周末必须落地，而不是第 8 周再改。**

**本路线默认假设（可改，但要写进日志）**

① 业务以中文 query 为主；② 图库在 10 万～千万级，先用 1k–5k 子集做闭环； ③ 可以访问 GPU 做教师推理与学生训练，但推理部署要瘦； ④ 「相似」会随业务清晰化——前两周用人工准则钉死一版，后面只增量修订。

## 二、一句话结论：蒸馏完全可行

**可以、而且应该蒸馏。** 0.6B 上限约束的是**学生 / 上线模型**，不是教师。 Jasper / Stella、jina-v5-text（蒸馏 Qwen3-Embedding-4B）、多家 Embedding 蒸馏实践都证明： 用大教师的排序分布、相似度、伪 query，能显著抬升小模型在检索任务上的表现。 对你而言：教师可以是 2B–8B 的 CLIP / SigLIP / DINOv2-g / VLM embedding；学生卡在 ≤0.6B。

#### 蒸馏什么

*教什么，不教参数拷贝*

- 配对相似度 / 排序 soft label
- 教师 embedding 的 MSE / cosine 对齐
- 合成 query、caption、hard negatives
- 多教师（视觉教师 + 文图教师）

#### 不蒸馏什么

*避免无效折腾*

- 整网层对层模仿（双塔结构常常对不齐）
- 只蒸馏分类 logits 而忽略检索排序
- 教师与任务空间不一致（用纯文本教师硬做文搜图）

#### 和「选型」差在哪

*训练世界观*

- 选型：拿现成权重直接 embed
- 自训：定任务 → 建数据 → 训学生
- 蒸馏：教师只是数据增强与 soft 监督源

推荐训练配方（概念级，非唯一） 文搜图学生（双塔，总参 ≤0.6B）: L = λ1 · L_contrast(图文对) + λ2 · L_distill(学生相似度 ‖ 教师相似度) # 或 KL on ranking + λ3 · L_embed(学生图像/文本 vec ‖ 教师 vec) # 可选 图搜图学生（视觉编码器 ≤0.6B）: L = μ1 · L_image_contrast(同图增广 / 同实例对) + μ2 · L_distill(学生 ‖ DINO/教师图像塔) + μ3 · 领域度量学习（若有同款 ID）

## 三、你必须先学会的概念地图

按「能不能独立讲清楚」验收。讲不清就别急着开多卡训练。

| 概念 | 你要能回答的问题 | 为什么跟你的任务有关 |
| --- | --- | --- |
| 双塔 / Dual-Encoder | 为什么文搜图要用独立编码 + 向量相似度？ | 决定学生骨架与推理成本 |
| InfoNCE / 温度 τ / 大 batch | 负样本从哪来？τ 太大太小会怎样？ | 对比学习基本功 |
| Hard Negative | 假负例会怎样毁掉训练？ | 领域数据质量生死线 |
| 图搜图：实例 vs 语义 | 你的「相似」判决书怎么写？ | 决定要不要 DINO 式教师 |
| 跨模态对齐 | 为什么纯文本 embedding 不能文搜图？ | 避免错误底座选型当学生初始化 |
| Embedding 蒸馏 | 蒸馏相似度、蒸馏向量、蒸馏排序各适合何时？ | 大模型怎么帮小模型 |
| Teacher–Student 空间 | 教师维度 4096、学生 512 怎么对齐？ | 投影头 / 关系蒸馏 |
| 评测协议 | Recall@K、mAP、人工侧盲评怎么分工？ | 没有协议就没有迭代 |

## 四、12 周学习总路线

- **第 1–3 周 · 阶段 A 基础**  
  钉死任务定义与双任务架构决策；手推一遍对比损失；跑通「冻结现成编码器 → 建索引 → 人工看 TopK」仅作**认知基线**，不作为最终交付。

- **第 3–5 周 · 阶段 B 数据**  
  建立图文对、图搜对、难负例流水线；引入大模型做 caption / 伪 query / 教师打分——**数据即模型**。

- **第 5–7 周 · 阶段 C 首次自训**  
  从公开小骨干初始化学生（≤0.6B），先只做对比学习，不上复杂蒸馏；拿到第一条可复现训练曲线。

- **第 7–10 周 · 阶段 D 蒸馏硬化**  
  接入教师相似度 / 向量 / 排序蒸馏；多教师；针对失败 case 增广与难负例刷新。

- **第 10–12 周 · 阶段 E 收口**  
  固化评测集与发布标准；量化；写清「为何这么训」的实验日志；规划下一轮数据飞轮。

> **说明**：节奏可比考研复试安排：**每周必须有可演示产物**（一页指标表 / 一个 Gradio / 一份失败案例集），否则学习没有锚点。

## 五、阶段 A · 基础（第 1–3 周）

### 学习目标

- 能用自己的话区分：骨干结构 vs 交互范式 vs 任务目标（不要混谈）。
- 手写 InfoNCE（含 in-batch negative）并能指出代码里每一项对应什么。
- 做出「相似判决书」v0：图搜图、文搜图各 20 条正例准则 + 反例。
- 拍板：单双塔合并，还是两个 ≤0.6B 学生。

### 行动项

| 周 | 学 | 做 | 产出 |
| --- | --- | --- | --- |
| W1 | 双塔对比学习；CLIP 训练目标直觉；图搜图实例/语义二分 | 写《相似判决书》v0；列出业务失败样例 30 张 | 判决书 Markdown + 样例板 |
| W2 | Hard negative；温度与 batch；评测 Recall@K | 冻结任意小双塔，仅在 500 张图上建索引，人工翻 TopK（只为建立感觉） | 基线观感笔记（非模型选型结论） |
| W3 | 蒸馏用于检索的三种形式（vec / sim / rank） | 架构决策评审：1 模还是 2 模；学生容量粗预算（视觉塔 / 文本塔参数比） | 一页 ADR：Architecture Decision Record |

**本阶段刻意不做**

不扫榜单、不纠结「该买谁的 API」、不追求一次训满数据。 目标是把问题表述训练成肌肉记忆。

## 六、阶段 B · 数据工程（第 3–5 周）

> 自训路线里，**数据设计权重大于学生初始化权重**。
> 大模型首先被当成数据机：写 caption、改写 query、挖难负例、打软分——然后再谈参数蒸馏。

#### 文搜图数据

*pairs / triples*

- 正对：图 + 真实标题 / 属性 / 人工 query
- 扩展：VLM 多风格改写（短查询、口语、属性枚举）
- 负例：随机 → BM25/视觉相似假相关 → 教师难负例
- 保存字段：image_id, text, source, hard_level

#### 图搜图数据

*pairs / identity*

- 同实例多视角 / 增广对（自监督起步）
- 有 ID 时：同款为正、易混款为 hard neg
- 近重复检测集（质量回归用）
- 明确禁止：把「同类」强行标成「同实例」除非判决书允许

### 大模型在数据阶段的合法用法

| 用法 | 输入 | 输出 | 风险与护栏 |
| --- | --- | --- | --- |
| Caption / 属性抽取 | 图 | 多条中文描述 | 抽检幻觉；属性白名单 |
| Query 改写 | 已有文本 | 检索向短 query | 保留实体，禁虚构 SKU |
| 教师打分 | (q, img) 或 (img, img) | 相似度 / 排序 | 只在候选池内打分，控制成本 |
| 难负例挖掘 | query + 检索 TopN | 过滤假负例后的 hard set | 正样本分数锚定（positive-aware） |

**验收标准（W5 末）**：至少各有一份可训练 JSONL——文搜图 ≥5万对（可含合成）、图搜图 ≥同等规模增广对或实例对； 另有**冻结评测集**（文搜图 ≥200 query，图搜图 ≥100 query），从此禁止用评测图调参时泄漏增强。

## 七、阶段 C · 第一次自训（第 5–7 周）

这一阶段的心理建设：**第一次训练允许很丑**，但必须可复现。蒸馏留到下一阶段。

#### 学生怎么来

*初始化 ≠ 最终选型交付*

- 公开小骨干做起点（Vision / Text）
- 总参裁切 / 缩宽 / 减层，卡死 ≤0.6B
- 记录初始化来源与许可证

#### 先训什么损失

*KISS*

- 文搜图：标准图文 InfoNCE
- 图搜图：增广对比或实例三元组
- 暂不加蒸馏项，建立基线曲线

#### 训练纪律

*可复现*

- 固定 seed、配置进仓库
- 日志：loss、Recall@K、样例 TopK
- 一次只改一个变量

**建议的最小实验矩阵（C 阶段）**

① 只有 in-batch neg；② + BM25/视觉 hard neg；③ 改 τ；④ 改学习率。 四个实验跑完，你才有资格说「我知道自己的数据吃哪一套」。

> **说明**：若文搜图与图搜图共用一个双塔学生：可先主训图文对比，再弱开图像–图像对比辅助头，避免两任务互相拆台。 权重 λ 用验证集扫，不要拍脑袋。

## 八、阶段 D · 蒸馏与硬化（第 7–10 周）

### 学习目标

弄清楚：**教师大，并不自动等于学生强**——取决于教师任务是否对齐、soft label 是否可信、学生容量是否接得住。

#### 文搜图蒸馏配方

*跨模态教师 → ≤0.6B 双塔学生*

- 教师：更大 CLIP / SigLIP / 多模态 embedding（可 >0.6B）
- 关系蒸馏：同一 batch 内相似度矩阵对齐
- 可选：文本侧 / 图像侧向量经投影后 MSE
- 继续保留真实图文对的硬标签对比项

#### 图搜图蒸馏配方

*视觉教师 → ≤0.6B 视觉学生*

- 教师：更强自监督视觉模型或检索微调大模型
- 特征蒸馏 + 同实例度量学习
- 对「实例相似」任务，优先视觉教师而非纯 CLIP 语义教师
- 用教师挖难负例刷新训练集（每 1–2 epoch）

### 行动清单（D 阶段）

| 步骤 | 行动 | 通过标准 |
| --- | --- | --- |
| D1 | 冻结教师，缓存库内图像向量与部分 query 向量 | 缓存可复用，教师推理成本受控 |
| D2 | 只加关系蒸馏，λ 从小扫到大 | 验证集 Recall 不低于纯对比基线 |
| D3 | 加入教师挖的 hard neg | 失败 case 集中类型减少 |
| D4 | 多教师冲突实验（视觉教师 vs 文图教师） | 写清哪类 query 受益于哪个教师 |
| D5 | 容量探底：学生减层 / 缩维后再蒸 | 仍 ≤0.6B，且相对不蒸有稳定增益 |

**阶段心法**：蒸馏是把「教师算力」换成「更好的训练信号」； 上线仍是学生。若蒸完没有增益，先查任务是否错位（例如用语义教师硬蒸实例图搜图），而不是先怪学生太小。

## 九、阶段 E · 评测、部署、迭代（第 10–12 周）

#### 评测体系

*自动 + 人工*

- 文搜图：Recall@1/5/10、nDCG（有等级时）
- 图搜图：实例 mAP 或同款 Recall；近重复 AUROC
- 固定「难吃」样例板每周回归
- 侧盲评：两人独立打分，防自嗨

#### 部署与约束回收

*单模 ≤0.6B*

- 导出前核对参数量脚本
- int8 / 维数截断（若训了 MRL）
- 索引构建流水线与增量更新
- 延迟：单张编码 P99 目标写进 SLA

**数据飞轮（第 12 周之后的常态）**

线上难例 → 人工/弱标 → 进训练集 → 教师再挖负例 → 短训学生 → 对比冻结评测集 → 发布。 没有飞轮，模型会停在实验室分数。

## 十二、反模式：别再只做选型

#### 反模式

- 每周换候选模型名，没有训练曲线
- 没有冻结评测集就声称 SOTA
- 用纯文本小模型幻想文搜图
- 教师与任务空间错位还猛蒸
- 把 0.6B 上限理解成「不能用大教师」

#### 正模式

- 判决书 → 数据 → 基线 → 蒸馏 → 飞轮
- 大模型优先服务数据与 soft label
- 学生容量死磕 ≤0.6B 并参数量验算
- 一次只验证一个假设
- 每周可见的失败案例进步

> **收束**：你的目标是训练出（可能经蒸馏得到的）≤0.6B 任务模型，而不是在报告里圈一个 HF 模型名。
> 蒸馏合法且推荐；前提是任务定义清楚、数据诚实、评测冻结。
> 按本文 12 周推进，第 12 周末应交出：架构 ADR、两份数据规范、一条可复现训练配方、≤0.6B 权重、以及下一轮飞轮计划——而不是又一份选型表。

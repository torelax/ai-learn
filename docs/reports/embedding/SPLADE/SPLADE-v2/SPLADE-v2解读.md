# SPLADE v2 补充解读：三条改进不要混成一条

> 本页从表示、训练和部署三个角度解释 v2，例子为教学推导。

## Max pooling 不是“只取最重要的一个词”

对某个词表词 vehicle，输入中“汽车”“道路”“发动机”等位置都可能提供激活。sum 会累计这些贡献，max 只取最强的位置；换到另一个词表词 repair，又会选择自己的最大值。输出仍是一整条稀疏词表向量。

这与 ColBERT 的 MaxSim 也不同：SPLADE 在**编码阶段**把位置维聚合掉，之后可用稀疏内积；ColBERT 保存位置向量，到**查询评分阶段**才对每个 query token 寻找匹配的 document token。

## 文档单侧与双侧的取舍

SPLADE-doc 将在线查询限制在原始词项上，查询侧的语义泛化更多依赖文档提前扩展。它适合查询编码预算很紧的场景，但长尾表达若未被文档扩展覆盖，就可能丢召回。双侧扩展则有更多匹配机会，也增加在线编码和 posting 遍历成本。

因此需要明确预算主要卡在哪里：GPU 查询编码、CPU 倒排检索、索引内存还是端到端尾延迟。不同瓶颈可能导向不同变体。

## 蒸馏为什么仍需重新挖负例

只学习 BM25 提供的词汇近邻，学生可能学会排除字面相似的文档，却看不到自己会误召回的语义近邻。用上一阶段学生检索，再让教师评价这些候选，相当于把训练分布推向学生真正困难的区域。

但教师也会犯错，难负例还可能包含漏标正文档。Margin-MSE 提供软差距，不等于自动消除假负例。生产训练应结合人工或可靠规则检查高分冲突样本。

## 从这里读后续 SPLADE 工作

把改动分成三个维度记录：表示如何聚合、训练使用什么教师与负例、部署采用什么查询端和索引引擎。后续模型名可能同时改变三项，只有按轴对齐才知道收益来自哪里。单独说“v2 换成 max 所以得到 .368”会把蒸馏贡献错误归给池化。

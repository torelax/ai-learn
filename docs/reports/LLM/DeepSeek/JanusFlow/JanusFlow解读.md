# JanusFlow：补充解读

> 换成 flow 后，LLM 在生成中究竟做什么？以下为直觉解释与应用延伸，论文内容见 [精炼主笔记](JanusFlow详解.md)。

## 为什么换成 flow 后仍然是统一模型

“统一”指共享大部分表征计算，而不是所有输出都必须是词表 ID。文本的自然建模单位是离散 token，图像可以在连续潜空间中逐步还原；二者通过不同输出头和损失接入同一个骨干。

![连续生成与语义理解共用骨干](figs/S3-F2-01.png)

图中单独的生成模块承担从空间潜变量到序列隐藏状态的转换。实现上要正确处理时间条件、注意力掩码和输出形状，不能把它当作只换最后一层的文本任务。

## 表示对齐比“共享参数”多做了什么

共享参数仅提供信息可能流通的通道；对齐损失明确要求生成过程的中间状态保留语义结构。停止目标端梯度避免双方同时漂移而轻易降低损失，却失去原有语义参照。

## 分辨率实验值得保留

256 与 384 的结果说明，图像看起来更精细和提示遵循更准确是不同维度。选生成模型时最好用自己的提示集，单独统计计数、关系、属性绑定和文本渲染，再看审美与时延。

## 用一个具体场景串起来

在某个t，LLM收到整张含噪latent的表示和时间条件，输出对应速度，再更新整张latent。它不是先写一句“请扩散模型画图”就结束，也不是每轮只补一个像素。

REPA让这些含噪中间表示接近干净图像的语义编码，可理解为在学习重建细节之前先建立有用结构。该训练约束可能帮助收敛，但是否在所有分辨率和规模都有效，需要新的控制实验。

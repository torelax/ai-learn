# DeepSeek-V3.2-Exp：补充解读

> 索引器省下的是昂贵的哪部分？以下为直觉解释与应用延伸，论文内容见 [精炼主笔记](DeepSeek-V3.2-Exp详解.md)。

## DSA 学的是“先看哪里”

可以把索引器理解为模型内部的检索层：它不是在外部文档库里找文章，而是在当前层的历史 token 中筛选 KV。选中哪些位置和如何融合这些位置，是两套计算。这样允许用很便宜的打分筛掉大多数候选，再把昂贵算力留给少量条目。

## 稀疏化不是直接改一个 mask

没有 warm-up，随机索引器会先让模型看不到需要的信息，主模型和选择器的学习目标也可能互相干扰。先用稠密注意力教索引器，再继续训练主模型适应选择误差，是迁移已有 checkpoint 的关键。

943.7B token 的稀疏继续训练本身也是实质成本。推理更便宜不代表任何团队都能把已有模型低成本改造成同等效果的 DSA 模型。

## 与 NSA、MLA 的关系

MLA 压缩每个 KV 条目的表示；DSA 减少每次真正参与主注意力的条目数。NSA 研究压缩、选择与滑窗分支及其原生训练，DSA 则以轻量索引器做 token 级选择并迁移已有模型。三者解决的瓶颈相关，但实现路径和验证设置不同。

## 怎样判断部署是否值得

需要同时测目标长度分布下的 prefill、decode、显存、batch 容量与任务正确率。长 prompt 的收益可能很大，短 prompt 却可能主要受 MoE、通信或框架开销限制。最好固定 GPU、并发、输出预算后比较，而不是只比较注意力复杂度公式。

## 用一个具体场景串起来

扫描全部历史的轻量低精度分数，并不等于完整多头attention。DSA先付便宜扫描，再让昂贵主attention只看top-k，因此indexer仍二次复杂度也可能有实际长文收益。

但短序列上选择和稀疏kernel的固定成本会占主导，报告才保留masked-MHA短路径。是否值得部署，需要测你的长度分布和整模型成本，而不能只比较渐近式。

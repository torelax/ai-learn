# DeepSeek-OCR：用视觉 token 压缩并重建文档文本

> 💡 DeepSeek-OCR 先用局部视觉编码和卷积把文档压成少量视觉 token，再用小激活量 MoE 解码文字与结构，研究光学上下文压缩的能力和边界。
>
> [论文](https://arxiv.org/abs/2510.18234) · [官方仓库](https://github.com/deepseek-ai/DeepSeek-OCR) · [补充解读](DeepSeek-OCR解读.md)

长文本通常占用大量语言 token，而图像可以把文字以二维方式容纳在一页中。DeepSeek-OCR 研究的核心问题是：需要多少视觉 token，才能尽量准确地还原一页文本？它以 OCR 作为可检查任务，设计先局部提特征、再压缩、后全局建模的 DeepEncoder，并配合 3B MoE 解码器。实验同时覆盖压缩率扫描和真实文档解析，显示约十倍 token 压缩下仍能保持较高识别精度；但密集页面、低分辨率和高压缩会明显丢失信息。论文提出对话历史光学压缩等方向，尚未证明任意长上下文推理都能无损替换成图像。

## DeepEncoder：先处理高分辨率，再做全局注意力

![DeepEncoder 的局部感知、压缩与全局编码](figs/S2-F3-01.png)

前段采用约 80M 参数的 SAM-base、patch 16，以窗口注意力提取视觉特征；两个 stride=2 卷积在两个空间维各缩小四倍，使 token 数缩小十六倍，通道由 256 增至 1024；后段用去掉原始 patch embedding 的 CLIP-large 做全局语义建模。

例如 1024 方图先产生 $64\times64=4096$ patch，压缩后只剩 256 个 token 再进入全局注意力。这样不是让一个完整全局 ViT 先承受全部高分辨率二次开销，再在末尾减少输出。

## 分辨率模式与视觉 token 预算

| 模式 | 分辨率 | 视觉 token |
| --- | --- | ---: |
| Tiny | 512×512 | 64 |
| Small | 640×640 | 100 |
| Base | 1024×1024 | 256 |
| Large | 1280×1280 | 400 |
| Gundam | $n$ 个 640 局部块+1024 全图 | $100n+256$ |

通过位置编码插值支持多模式。Tiny/Small 直接缩放，Base/Large 保持比例补齐，实际有效图像 token 少于含 padding 的总量；论文用 $N_{valid}=\lceil N_{actual}\min(w,h)/\max(w,h)\rceil$ 估计有效数。

Gundam 局部块通常 2–9 个，小图退化为仅全局视图；更大的 Gundam-master 是训练后另用 6M 样本继续训练，避免超大图拖慢普通模式。因而表中的 token 上限与有效信息量、平均 token 量是不同概念。

## 解码器与数据引擎

解码器为 DeepSeek-3B-MoE，64 路由专家中激活六个，再加两个共享，激活约 570M 参数；根据视觉 latent 和文本提示，生成文本及布局标记。总参数 3B 不意味着只需装载 570M 权重。

数据分三类：OCR 1.0 为普通文档与场景文字；OCR 2.0 为图表、化学式、几何等结构解析；另有一般视觉数据与纯文本。最终采样比为 OCR 70%、一般视觉 20%、文本 10%。

文档收集约 30M PDF 页，中文英文约 25M、其余约百种语言共 5M。粗标签用 fitz 提取，精标签对中英文各 2M 页做布局与识别交错标注；小语种结合局部渲染、识别器训练和 flywheel 补充约 600k。另有 3M Word 文档，增强公式和 HTML 表格。

自然场景中英文各约 10M 样本；结构合成包含约 10M 图表、5M 化学式和 1M 几何图。图表目标是 HTML 表格，化学式使用 SMILES，几何使用结构化几何表示，不能都笼统称为纯文字转录。

## 两阶段训练与工程配置

先用小语言模型配合 NTP 单独训练 DeepEncoder：OCR 数据加 100M LAION 样本，两轮、batch 1280、长度 4096、AdamW、学习率 $5\times10^{-5}$ 余弦调度。

再接入 MoE 解码器，四段流水线：SAM+compressor 冻结置于 PP0；CLIP 可训练置于 PP1；十二层 LLM 分到 PP2/3。20 个八卡 A100-40G 节点、DP40、global batch640，长度8192，初始学习率 $3\times10^{-5}$。报告的 70B 多模态 token/day 是训练吞吐，不是每天识别出的文档文字量。

PPT 较稀疏，64 token 可能足够；书页、报告约100 token 能较好处理；报纸通常 4–5k 文字 token，需要 Gundam 或 master。压缩边界与版式密度、缩放清晰度相关，而不是所有页面共享固定十倍最优值。

定性结果展示图表、化学、几何、多语言与一般视觉接口；一般视觉样本只占20%，报告也明确它不是以全面 VLM 能力为目标的模型。

## 展望与证据边界

把更旧文本渲染得更小来模拟遗忘，是论文提出的应用方向；它没有完整实验验证长期对话、信息选择、幻觉与任务准确率。视觉编码本身也有计算和读图开销。

本文可靠的结论是少量视觉 token 可以承载相当多的文档文字，并且编码器结构与分辨率决定重建质量。把这种能力发展为通用上下文压缩，还需评测 OCR 以外的下游任务，以及压缩、解码和注意力的总成本。

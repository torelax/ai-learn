# DeepSeek-OCR-2：补充解读

> 因果query是在排序，还是在生成文字？以下为直觉解释与应用延伸，论文内容见 [精炼主笔记](DeepSeek-OCR-2详解.md)。

## 重排的不是一个可打印的页块列表

查询输出是对整幅图的学习表示，每个向量可以混合多个位置的信息。把它理解成显式排序算法会误解方法：没有保证第 17 个查询就对应原图第 17 个阅读区域。

![查询之间的因果依赖](figs/S3-F5-01.png)

图中视觉端保持双向可见，查询端按顺序组织信息。它为“后面的表示能利用前面已经聚合的内容”提供结构偏置，最终是否符合人类阅读顺序由训练决定。

## 因果掩码不等于串行生成成本

文本生成的下一 token 尚未知，所以必须逐步采样；这里所有查询 embedding 已经存在，可以像训练文本 Transformer 那样并行计算掩码注意力。真正串行的仍是后面的文本解码。

## 如何用于文档系统

相比平均 OCR 分数，跨栏段落的先后顺序、表格行列关系和标题归属更影响后续 RAG 的 chunk 质量。可用 OCR 2 做抽取，但应按文档类别抽样检查这些结构；重复率降低只是运行质量的一项信号。

## 用一个具体场景串起来

一组learnable query并行进入带三角mask的Transformer，各位置读取全图与此前query，得到有序语义表示；它们不是逐字自回归采样，也不保证对应一个可打印的页面块列表。

所以更好的阅读顺序是最终任务证据，不是从mask形状自动推出的定理。把输出接文档系统时，仍需检查漏行、重复、表格结构和类别差异，尤其报纸等高密度场景。

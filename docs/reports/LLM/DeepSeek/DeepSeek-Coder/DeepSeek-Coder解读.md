# DeepSeek-Coder 补充解读

> 训练序列为什么会影响编辑器里的补全？以下为直觉解释与应用延伸，论文内容见 [精炼主笔记](DeepSeek-Coder详解.md)。

## 仓库排序可以理解为数据层面的检索

同一个函数的使用方和定义方如果分散训练，模型更难学习项目关系。依赖排序把相关上下文提前，相当于在训练数据里构造更有用的可见信息。它不是完整程序分析：动态 import、配置注入和构建规则仍可能不在静态依赖里。

## FIM 训练与编辑器补全为什么相配

Python 编辑时经常保留函数前半段和后面的调用，仅修改中间部分。纯左到右续写看不到后缀；FIM 通过重排把后缀移入条件。这不需要双向 attention，因果模型也能根据已经出现的后缀补出 middle。

## 短函数得分不能替代项目修改成功率

HumanEval 测函数生成，DS-1000 更接近库调用，仓库补全又考察上下文利用。真实维护还涉及定位文件、理解测试和保持接口，往往需要工具与 agent。模型分数高是组成条件，而不是完整工程能力。


## 用一个具体场景串起来

设两个文件：A定义函数，B导入并调用。把A放在B前，预测B时可见定义；乱序则可能只有函数名。仓库排序是在训练数据中提高相关依赖可见的机会，不是运行时接入了一套检索服务。

FIM则改变预测条件：写普通下一行只看到前文，编辑器填一个函数体却常有后文。训练把后缀搬到待补内容前面，让模型学习利用双侧上下文。推理提示若仍只给前缀，就不能期待完整兑现FIM能力。

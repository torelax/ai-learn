# Native Sparse Attention：同时面向训练与推理的原生稀疏注意力

> 💡 NSA 把历史信息分成压缩摘要、按查询选择的原始块和局部窗口，让模型从训练起学习稀疏模式，并用连续块访存将理论节省变成 GPU 效率。
>
> [论文](https://arxiv.org/abs/2502.11089) · [补充解读](Native-Sparse-Attention解读.md)

长上下文的注意力开销不仅来自计算，还来自 KV 读取。推理阶段临时删除 token 虽能减少部分访问，却可能有选择成本、训练分布不一致和随机访存低效等问题。NSA 因而从预训练起使用稀疏结构，并同步设计硬件友好的算子。它以低成本压缩分支扫描全局，用其注意力分数选择重要原始块，再让独立滑窗处理局部模式。27B 总参数、3B 激活的实验检验通用能力、长文及推理，效率部分则单独衡量 attention kernel，避免把算子加速与整模型吞吐混为一谈。

## 三分支结构

![压缩、选择和滑动窗口](figs/S2-F2-01.png)

对于 query $q_t$，三路分别构建压缩、选择和局部 KV，输出用独立 sigmoid gate 混合：

$$
o_t=\sum_{c\in\{cmp,slc,win\}}g_t^c\operatorname{Attn}(q_t,\widetilde K_t^c,\widetilde V_t^c).
$$

门控来自输入特征，不强制三路权重之和为 1。分支保持独立 KV，避免局部模式太容易学习，使训练只依赖局部窗口而不发展长程选择。

## 压缩：低成本全局扫描

将长度 $l$、步幅 $d$ 的连续块经含块内位置编码的 MLP 压成一个 KV：$\widetilde k_i=\varphi(k_{id+1:id+l})$。主配置 $l=32,d=16$，块重叠减少边界割裂。

压缩分支计算 $p_t^{cmp}=\operatorname{softmax}(q_t^T\widetilde K_t^{cmp})$。它保留全局粗信息，同时为下一步选块提供便宜的重要性估计，而不先计算完整 token 级 attention 矩阵。

## 选择：从粗分数回到原始细节

选择块大小 $l'=64$，按压缩块与选择块的空间覆盖关系累加重要性。在 GQA 组内再跨 query heads 求和，统一选择 top-$n$ 块，主配置 $n=16$，其中固定包含最初一个块和两个局部块。

选中后读取的是块内**原始 KV**，不是压缩向量。全局摘要负责发现相关区域，精细分支负责恢复细节，因此无需假定一个压缩 token 足以保留全部信息。

连续块有两个理由：注意力重要区域常局部连续，GPU 也更适合合并访存与 Tensor Core 块计算。按单 token 随机索引即使 FLOPs 更低，也不保证更快。

## 滑窗与算子设计

局部窗口 $w=512$ 单独处理临近依赖，使另外两路专注全局和选择。主要实验采用四个 GQA groups、64 heads，$d_k=192,d_v=128$。

![组内 query 共享稀疏 KV 的 kernel](figs/S3-F3-01.png)

Triton kernel 不按相邻时间 query 简单分块，因为它们可能选中不同 KV。它在同一位置加载一个 GQA 组全部 query heads，复用该组共同的选块与 KV，再把 query/output 外循环交给 grid scheduler。这减少重复读和不均衡。

## 训练配置与通用结果

模型为 30 层、hidden 2560 的 GQA+DeepSeekMoE，总 27B、激活 3B，72 路由专家、两个共享专家、top-6。NSA 与 Full Attention 都用 270B token、8K 长度预训练，再以 YaRN 继续训练与 SFT 到 32K。

## 效率与实测口径

在相同 Triton 后端对比 FlashAttention-2，64K 上 attention 前向最高约 9 倍、反向约 6 倍。它们是算子测量，不是端到端训练整体加速。

| Context Length | 8192 | 16384 | 32768 | 65536 |
| --- | --- | --- | --- | --- |
| Full Attention | 8192 | 16384 | 32768 | 65536 |
| NSA | 2048 | 2560 | 3584 | 5632 |
| Expected Speedup | 4 $\times$ | 6.4 $\times$ | 9.1 $\times$ | 11.6 $\times$ |

表按每步需读取的 KV 数估算解码访问收益，64K 从 65,536 减到 5,632，约 11.6 倍是该访问量模型的预期比值。全模型还有 FFN、选块、通信与投影开销，不能将其直接当作服务 QPS 倍数。

## 替代方案与局限

作者尝试 key clustering，但重聚类、类大小不均、顺序训练和 EP 负载带来额外困难；exact top-k 又要先读全部 key，选择本身抵消节省。NSA 通过可训练摘要和块级选择折中。

全局压缩 token 数仍随上下文长度增长，所以这里不是对任意长序列提供严格固定时间。固定分块、窗口和稀疏预算也可能漏掉跨块细节。论文支持的是算法与 kernel 共同设计，并在训练阶段学习稀疏模式，而不是事后仅按一个稀疏率推断真实效率。

# Native-Sparse-Attention：补充解读

> 为什么先压缩，再回到原始块？以下为直觉解释与应用延伸，论文内容见 [精炼主笔记](Native-Sparse-Attention详解.md)。

## 为什么 FLOPs 少还可能更慢

GPU 擅长规则的大矩阵运算。若为了省一次乘法增加大量随机索引、内核启动和离散读取，运行时间反而会上升。NSA 的贡献需要同时看“选哪些 token”和“怎么搬这些 KV”。

![连续块访存](figs/S3-F3-01.png)

图中 GQA 组共享选择集合，是算法配合硬件的具体例子。每个 head 独立挑最重要 token 看似更精确，却可能导致内存访问量随 head 数膨胀。

## 压缩与选择为什么互补

只压缩会丢细节，只选择又需要先知道哪里重要。NSA 用便宜的全局概览提出候选，再回到原始 token 精读。这和检索中的粗排—精排有相似的计算分配思路，但它发生在每层注意力内部，表示和路由会共同训练。

## 不要将 NSA 与 DSA 混为同一算法

后续 V3.2 的 DeepSeek Sparse Attention 使用专门的轻量索引器，NSA 则是压缩、选择、窗口三分支。两者共享稀疏化目标，具体结构、训练和 KV 组织却不同。选型时需检查模型原生支持的算子。

## 用一个具体场景串起来

把一页摘要成一句话可以知道哪里相关，却丢掉精确数字。NSA压缩分支负责便宜地发现区域，选择分支再读取原始KV，类似先看摘要定位，再回到原文查证。

若选token很随机，读显存和索引成本可能抵消少算的FLOPs。按连续块访问、GQA组内共享KV与专门kernel，是算法实际快起来的条件，不是实现之后才随便补的细节。

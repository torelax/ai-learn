# DeepSeekMoE 补充解读

> MoE 的“大”与“省”分别发生在哪里？以下为直觉解释与应用延伸，论文内容见 [精炼主笔记](DeepSeekMoE详解.md)。

## 共享专家更像公共计算路径

“共享专家负责公共知识”是设计动机，实际学到的表示不会自动对应一张可读的学科表。理解它时，可以想象所有 token 都经过一条公共 FFN，再按输入选择补充变换；是否真的减少冗余，仍需通过替换、移除和路由统计验证。

## 总参数、激活参数、显存是三件事

16.4B 总参数、2.8B 激活参数意味着单 token 只计算部分专家，不意味着加载 2.8B 权重就能运行。优化器状态、专家权重和分布式通信仍受总容量影响。做部署选型时，应分开权重常驻成本、KV 缓存和 token 执行成本。

## 细粒度不是越细越好

理论上更多小专家有更丰富组合，硬件上却可能变成小矩阵、稀疏分发和通信碎片。需要在模型质量与实际吞吐之间选择粒度；V2、V3 后续的路由限制和通信优化，正是在兑现这里的理论节省。


## 用一个具体场景串起来

若把一个大专家切成四个小专家，每token激活的小专家数也要相应调整，才可能保持接近的FFN计算。比较只把专家数翻倍、同时多算一倍的设置，并不能证明细分本身有效。

共享专家类似每条请求都会执行的公共处理，路由专家承担差异部分。但这是结构上的归纳偏置，不保证某个专家自然对应“数学系”。把专家激活当解释标签，需要额外干预与任务统计，而不能只看一次路由。

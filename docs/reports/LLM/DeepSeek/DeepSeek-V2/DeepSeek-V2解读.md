# DeepSeek-V2 补充解读

> MLA 节省的是哪段执行路径？以下为直觉解释与应用延伸，论文内容见 [精炼主笔记](DeepSeek-V2详解.md)。

## 低秩分解不是压缩文件

MLA 学习的是可用于 attention 的潜变量，不是训练完后随意把历史 K/V 做 PCA。压缩维度、上投影与 query 变换都在模型训练中配合，部署再利用矩阵乘法结合律避免展开所有历史缓存。

## RoPE 解耦解决了什么障碍

位置旋转随 token 位置变化，不能普遍塞进一个固定权重矩阵里。把内容和位置分支分开后，大部分内容缓存可压缩，小型位置 key 单独保留。这也是理解 MLA 与普通低秩线性层区别的关键。

## 吞吐提升为何不能照搬到单请求

缓存减少允许更大 batch，而批处理吞吐与单条请求延迟不是同一目标。V2 的最大吞吐数字还包含权重量化、KV 量化、负载长度分布与算子优化。服务中应分别测 prefill、decode、首 token 延迟及并发条件。


## 用一个具体场景串起来

普通多头缓存为每层每个历史token存多组K/V；MLA存共享latent，再将恢复矩阵吸收到query/output侧，避免每次完整展开缓存。仅做一次低秩投影、随后仍把全部多头K/V写回显存，不会得到同样缓存收益。

RoPE随位置旋转，使某些矩阵不能像普通线性层一样静态合并。将位置部分解耦，才能同时保留位置信息与吸收路径；这也是理解MLA不能只停留在“用了低秩”的原因。

# Prefix-Tuning：用逐层连续前缀控制生成

> **简述**：冻结语言模型，学习各层可被后续 token 读取的连续前缀，以很少的任务参数控制条件生成。<br>
> **paper**：[Prefix-Tuning: Optimizing Continuous Prompts for Generation](https://arxiv.org/abs/2101.00190) · ACL 2021<br>
> **code**：[XiangLi1999/PrefixTuning](https://github.com/XiangLi1999/PrefixTuning) · **refs**：[Adapter](https://arxiv.org/abs/1902.00751)、[GPT-3](https://arxiv.org/abs/2005.14165)<br>
> **backbone**：GPT-2 Medium/Large、BART Large · **date**：2021-01<br>
> **modality / languages**：文本；主要英语结构化生成与新闻摘要实验。

## 论文简介

为每个生成任务保存一份完整微调模型成本很高，而自然语言提示又不一定能有效控制较小的预训练模型。Prefix-Tuning 将任务条件变成连续前缀：冻结基座，直接学习前缀在各层的激活，让真实输入和生成位置通过注意力读取它；训练时用重参数化网络改善优化，推理时可物化任务前缀。论文在 GPT-2 的表格到文本任务上，以约千分之一任务参数取得接近或超过全量微调的结果，在 BART 摘要上则存在差距；低数据量和未见主题实验进一步显示前缀的泛化潜力。它减少的是任务参数和训练状态，仍需要基座反向传播，并带来前缀注意力与缓存开销，效果也依赖模型、任务和长度设置。

## 从自然语言提示到可学习的任务条件

全量微调改变模型本身，任务之间要维护不同权重。Adapter 将变化装进额外模块，但会引入新的网络计算路径。Prefix-Tuning 沿着“给模型一个适当上下文”的思路，寻找一种可训练、可共享基座的控制接口。

这里的前缀不必对应词表中的真实词，也不是从训练集挑几条例子放进上下文。它是由训练数据学到、同一任务的不同样本通常共享的连续参数。与只改输入 embedding 相比，论文进一步直接优化每层前缀激活，避免任务信号必须先经过完整主干才能影响深层。

## 方法：把前缀放进模型的激活递推

设输入和目标分别为 $x,y$，自回归序列为 $z=[P;x;y]$。对前缀位置，激活直接取自可训练矩阵；对真实 token，仍使用冻结 Transformer 的递推：

$$
h_i=\begin{cases}P_\theta[i,:],&i\in P_{idx},\\
\operatorname{LM}_{\phi}(z_i,h_{<i}),&\text{其他位置}.
\end{cases}
$$

$\phi$ 冻结，$\theta$ 参与训练。这里 $h_i$ 汇集同一前缀位置在各层的激活，不仅是输入层的词向量。对标准解码器注意力，可以把其作用理解为拼接任务级键值：

$$
\operatorname{Attention}(Q,[K_P;K_x],[V_P;V_x]).
$$

真实位置的查询可以读取前缀，前缀由此影响输入编码和目标生成。对 BART 这样的 encoder-decoder，论文同时为编码和解码路径提供前缀；不同架构涉及的注意力接口不完全相同，不能把一组 decoder KV 当成完整通用实现。

### 重参数化为何有用

直接优化全部前缀激活对学习率和初始化较敏感。作者先学习较小矩阵 $P'_\theta$，再经 MLP 得到所需前缀：

$$
P_\theta[i,:]=\operatorname{MLP}_\theta(P'_\theta[i,:]).
$$

训练后任务前缀可以预计算，因此该 MLP 不必留在推理路径中。它是在帮助优化同一任务级条件，不是为每个输入生成一个动态提示。任务损失仍是目标序列的条件对数似然，只是被优化的参数集合从整个模型变成前缀及其重参数化网络。

## 数据集和指标

E2E 将餐馆属性表变成描述；WebNLG 将知识三元组变成自然语言，并包含训练中未见的实体类别；DART 是开放域结构化生成。论文在这些任务上使用 GPT-2，报告 BLEU、NIST、METEOR、ROUGE-L、CIDEr 等指标。XSUM 用 BART 将新闻文章压成简短摘要，重点不仅是表达给定字段，还包括从长输入中选取内容。

比较对象包括全量微调、只微调顶部两层、不同参数预算的 Adapter。相同“前缀长度”在不同模型里不意味着相同任务参数量，因为逐层激活维度和注意力结构不同。

## 主要结果与边界

以下取自原论文表 1/2：

| 模型 / 任务 | 全量微调 | Prefix | 指标与设置 |
|---|---:|---:|---|
| GPT-2 Medium / E2E | 68.2 | 69.7 | BLEU，Prefix 约 0.1% |
| GPT-2 Medium / DART | 46.2 | 46.4 | BLEU |
| GPT-2 Large / E2E | 68.5 | 70.3 | BLEU |
| BART Large / XSUM | 37.25 | 36.05 | ROUGE-L，Prefix 约 2% |
| BART Large / XSUM | 37.25 | 35.05 | ROUGE-L，Prefix 约 0.1% |

结构化生成中，任务条件可以有效利用已有语言模型能力；摘要中，参数预算增加可以改善结果，但仍没有追平全量微调。不能把“0.1% 参数效果相当”写成所有任务统一成立。

## 消融和附录说明了什么

论文比较前缀长度、逐层前缀与只改输入 embedding、前置与插入式条件，以及初始化。总体上，适当增加长度有帮助，过长前缀并不持续改善；允许控制更多层的激活，也比仅在输入层间接影响更有表达力。用真实词激活初始化可以改善部分低数据量设置，随机前缀也不是总能立即优化到同样效果。

低资源实验与未见主题测试显示，冻结主干的前缀在部分设置下比全量微调更稳健。WebNLG 的未见类别和摘要的未见主题，检验的是特定类型的分布变化，不能直接推成任意域外泛化保证。附录补充超参、不同数据量、初始化及生成样例，应与主表的全数据结果区分。

## 成本与实际使用

标准多头注意力的逐层 K/V 前缀大致需要 $2Lmd$ 个参数，分别对应层数、前缀长度和隐藏维度；实际还要考虑 encoder-decoder 模块、KV 头数和任务头。它省掉主干的权重梯度和优化器状态，但仍要对主干进行必要反向传播，也增加注意力键值位置。

任务前缀可以为多任务共享一个冻结基座提供接口，但混合任务 batch 和缓存管理依赖实现。前缀一般无法像浮点 LoRA 一样直接加进原权重后删除条件路径。

## 结论与局限

这篇论文确立了逐层连续条件化的一条重要路线：冻结模型，学习如何让它为任务调用已有能力。它在结构化生成上展示了很好的参数效率，也明确暴露摘要质量、优化敏感性和额外前缀开销。后续 Prompt Tuning 简化到输入层，P-Tuning v2 则把深层提示更系统地用于 NLU，这些方法的历史关系应与它们各自的评测设置一起理解。

# YaRN 补充解读：位置尺度、注意力温度与有效上下文

> **核心理解**：YaRN 同时处理位置几何和注意力分布；修改最大长度只是配置变化，真正的长上下文能力仍需要训练与任务评测来确认。
>
> 本文是对 [YaRN](https://arxiv.org/abs/2309.00071v3) 的补充分析。作者的方法与原始结果见[论文精炼版](YaRN详解.md)；下文数值例子、推导与成本估算用于解释，不是论文新增实验。

## 相对位置公式为何没有自动带来无限外推

RoPE 内积依赖相对距离，说明位置作用具有特定形式，却没有要求模型对所有可能距离都学到合适行为。训练窗口限定了模型见过的相位与内容组合。

高频在短范围内旋转很多圈，局部相邻位置仍能产生明显相位差；低频在训练范围内可能还未转满一圈，把窗口拉长后会进入更多未见相位区域。YaRN 的分频设计是在这两种需求之间分配插值压力。

这也解释了为什么它按**频率维度**分段，而不是将文档前半段和后半段分别处理。同一个 token 的不同二维旋转平面会获得不同缩放。

## 一个数值例子：哪些频段被压缩

以原文的 $\alpha=1,\beta=32$ 和扩展倍率 $s=8$ 为例：

| 原窗口内的旋转圈数 | 混合系数 $\gamma$ | 新频率相对原频率 |
| --- | ---: | ---: |
| $r<1$ | 0 | $1/8$ |
| $r=16.5$ | $1/2$ | $0.5/8+0.5=0.5625$ |
| $r>32$ | 1 | 1 |

中间这一行来自对论文公式的代入。它显示的不是“所有位置缩短八倍”，而是低频承担更大压缩、高频保留局部变化。

还要注意坐标选择。$r(d)=L b^{-2d/D}/(2\pi)$ 随维度索引 $d$ 指数变化，因此在 $r$ 上线性过渡和在 $d$ 上线性过渡并不是同一曲线。阅读具体实现时，应核对 ramp 的自变量、边界取整和混合方向；仅看到参数同名不足以确定逐维频率完全相同。

## 幅度、logits 倍率与温度是三个不同的数

YaRN 的经验式给出：

$$
a=\sqrt{1/t}=1+0.1\ln s.
$$

当查询与键都乘以 $a$，二者内积会乘以 **$a^2$**。因此 $a$ 是向量幅度系数，$a^2$ 是 logits 放大倍率，$t=1/a^2$ 才是注意力温度。

以 $s=8$ 为例：

$$
a\approx1.208,\qquad a^2\approx1.459,\qquad t\approx0.685.
$$

降低温度会让给定 logits 的 softmax 更集中。论文是通过 PPL 拟合得到经验式，不是在每次推理中根据实际注意力熵自动求解温度；也不能将它当作对所有模型、倍率和输入都成立的定理。

![原文图 4：幅度缩放的经验选择。](figs/A1-F4-01.png)

**图 4** 将幅度与困惑度联系起来，支持温度调整的经验价值。正文与图注写 896 篇样本，图内标题却写 56，原文未解释这处数量差别；不宜据此精确推断实验样本划分。

如果架构只对查询和键的一部分维度施加 RoPE，只放大旋转部分通常不再严格等价于放大整个内积。将论文迁移到此类实现时，需要分别检查未旋转维度和显式注意力缩放，避免重复或局部缩放。

## Dynamic Scaling 为什么会碰到缓存问题

静态 YaRN 在一个请求中使用固定频率。Dynamic Scaling 则随着长度增加改变倍率，使同一个历史位置也需要使用新的旋转角。

设某历史位置为 $m$，旧频率为 $\theta_{\rm old}$，缓存中已有旋转键 $R(m\theta_{\rm old})k_m$。当前查询改用 $\theta_{\rm new}$ 后，若继续使用旧缓存，内积中的角度就不再是统一新尺度下的相对位置。

在理想的二维旋转情形中，可通过补乘旋转恢复：

$$
k_m^{\rm new}=R\!\left(m(\theta_{\rm new}-\theta_{\rm old})\right)k_m^{\rm old}.
$$

这是旋转矩阵复合性质带来的解释式，不是论文报告的实现代码。若幅度也变化，还需处理幅度比；量化缓存等细节又可能影响数值误差。

论文给出的直接建议是缓存 RoPE 之前的表示。实际系统也可以采用其他维持一致性的办法，但需要明确缓存究竟保存了什么。单独改变最大长度、保留全部旧旋转键，并不能自动实现正确的动态缩放。

## 训练长度、配置窗口与有效长度分别指什么

YaRN 128k 模型的训练序列仍为 64k，配置倍率对应 128k，随后再用 PPL 和口令检索测量它实际能使用多长输入。这三个长度承担不同角色。

“训练较短、测试更长”说明长度泛化，但没有消除长文训练。按论文全局 batch 64、每条 65,536 tokens 估算，400 步约处理 **16.8 亿 tokens**；后续 200 步再处理约 **8.4 亿 tokens**。这是按配置计算的训练量，相比完整预训练小很多，却不是单卡快速调几个参数。

同样，“超过训练长度”不等于“无需再次训练”。本文 128k 主结果使用从 64k checkpoint 追加 200 步的模型；未经微调的 Dynamic-YaRN 是另一组实验设置，应分别理解。

## 为什么 PPL、口令检索与真实任务需要并看

PPL 衡量下一 token 建模；口令任务衡量从干扰文本中定位简单信息；真实长文问答可能还需要筛选证据、处理矛盾与多步整合。三者有联系，但不能互相替代。

论文给出一个很具体的例子：Code Llama 在较长上下文的 PPL 已经上升，13B 模型仍能在 128k 找回口令。这意味着“能找到某个数字”与“全部长文生成保持质量”之间存在差别。

99.4% 也是不超过有效窗口的多个测试长度的平均，而非每个长度、每个位置都相同的准确率。比较方法时，还应同时看模型规模、训练预算、输入领域和指标定义。

## 位置编码改动几乎免费，长序列本身仍然昂贵

论文的零额外开销针对在**同样长度**下替换预计算的旋转表示。将长度从 4k 提高到 128k，会增加 32 倍 token；常规全注意力的配对数量按二次关系增长，KV cache 则通常近似线性增长。FlashAttention 改善内存访问和中间结果存储，并不会让长序列成本消失。

举一个仅用于理解存储量的假设配置：32 层、32 个 KV 头、每头 128 维、FP16，单序列 128k 时，键和值缓存约占：

$$
2\times32\times131072\times32\times128\times2\ \text{bytes}=64\ \text{GiB}.
$$

该例不是对某个部署的实测；分组查询注意力、缓存量化、批量大小及并行方式都会改变具体数字。它说明“位置编码能够扩到 128k”和“当前设备能够经济地运行 128k”需要分别解决。

## 从原论文迁移到新模型时

应先明确原窗口、原 RoPE 基数、旋转维度与现有注意力缩放，再决定分频阈值和倍率。原论文经验式基于 LLaMA 系列得到；新模型可能已经有长文训练或不同位置编码配置，直接叠加同一缩放可能改变原有行为。

验证时需要把短任务保真与目标长文任务一起观察。13B 的 MMLU 从 55.8 降至 51.9，说明总体“较小退化”的描述仍可能掩盖对具体使用者重要的差异。哪个窗口值得启用，应由实际任务的收益和成本共同决定。

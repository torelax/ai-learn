第一幕 · 为什么要 on-policy

先看 SFT 的监督信号：一个 one-hot

给定标准答案，最大化答案里每个词的概率

这个位置该填「深色」，于是监督信号是：

   深色  →  1.0
   黑色  →  0
   长裙  →  0
   ...   →  0        其余 248317 个词全都是 0

它只告诉了模型一件事：哪个词是对的。
其他所有词一律记为「错」—— 但它们其实错得不一样。

第一幕 · 为什么要 on-policy

换成一个教师，让它在同一个位置前向一次

得到的不是一个词，而是一个分布

深色     0.909
黑色     0.066
长裙     0.006
深       0.005
连衣裙   0.004
这几个数多说了三件事

这个位置该是个颜色词 · 深色系是主流 · 「长裙」也说得通但不是重点
one-hot 把这三层全丢了。被丢掉的这部分信息，行业里叫 暗知识（dark knowledge）。

注意：到这一层为止，已经不需要标准答案了，需要的是一个在线的教师。
但这一层还没碰到真正的问题。

第一幕 · 真正的问题

而且误差会 自我放大

这是正反馈，不是线性累加

偏一点 → 前缀更陌生 → 下一步更容易错 → 前缀更陌生 → …
所以序列越长，差距越大。这也解释了为什么长文本生成、多轮对话、推理链对这件事更敏感。
换个说法

教一个人开车：只让他看你开，他上路一偏就不知道怎么办；
让他自己开、你在旁边随时纠正，他练的正好是他真会遇到的情况。

第一幕 · 这个词是从哪借来的

「on-policy」借自强化学习，但更像模仿学习

在强化学习里，它说的是：你用来学习的数据，是谁产生的

学习用的数据来自哪类比到我们这里
on-policy正在训练的这个模型刚刚自己产生的学生自己生成的句子
off-policy别人产生的，或者它自己很久以前产生的数据集里的标准答案
和它最像的，是模仿学习里的一个做法

让学习者自己动手，在它实际走到的每一个位置上问老师「这里该怎么做」，用这些答案去训练。
on-policy 蒸馏就是这个结构：学生自己生成（学习者动手），教师逐位置给分布（老师现场指点）。

模仿学习（imitation learning）：让模型模仿一个「专家」的行为来学习，而不是靠奖励试错。 上面那个做法在文献里叫 DAgger（2011）。
第一幕 · 这个词是从哪借来的

但它 没有继承强化学习最难的那部分

强化学习：只能拿到一个总分

整句话说完，给你一个分数。
哪一步做对了、哪一步坏了事，得自己推断。

这个推断很难也很不稳定。
对比
on-policy 蒸馏：每步都有答案

教师给的是每个位置一个完整分布。
等于每一步都直接告诉你答案。

不需要推断任何东西。

所以它比强化学习稳定得多、也好调得多。
代价是：你需要一个比学生强的教师 —— 而强化学习不需要。

第二幕 · 教师在做什么

②  教师 一个字都不生成

把「问题 + 学生刚说完的整句话」当成一个完整的输入，前向一次

输入 = [问题] + [一名 穿 绿色 裙 子的 女士 在 室内 走动 。]
                    ↑ 这整段是学生生成的，但对教师来说只是「输入」

一次前向，返回每一个位置的 top-64：
   位置 0 → 一位 .771 / 一名 .118 / …
   位置 2 → 深色 .909 / 黑色 .066 / …    （以下略）

教师不需要自己想该说什么，只需要评价「在这个前缀下，下一个词的分布是什么」。
这个能力所有语言模型天生就有。

第二幕 · 教师在做什么

一个容易搞错的细节：教师返回的分布不受温度影响

请求里确实写了 temperature=0，但它管的不是我们要的东西

请求：prompt_logprobs=64,  max_tokens=1,  temperature=0
                                          ↑
              只作用于教师会生成的那 1 个 token —— 而那个 token 我们直接丢掉

我们真正要的分布走的是另一条路

推理引擎内部：logits.log_softmax(dim=-1)
              ↑ 直接对原始分数取对数概率，中间不除任何温度

所以教师返回的是它最原始、未经任何缩放的判断。
真正的温度缩放是后面在训练代码里做的 —— 第三幕会专门讲温度出现在哪几处。

第二幕 · 分词这一关

先说清 token 和分词是怎么回事

模型不认识文字，只认识编号

分词器负责把一段文字切成若干片段、每个片段给一个编号。
主流用的是 BPE：从字节开始，把高频相邻组合反复合并成更大的片段。
切分结果
一名
穿
绿色
裙
子的
女士

所以一个片段可以是一个字，也可以是好几个字。
上面的「子的」是一个 token，不是两个字 —— 这一点马上会变得很关键。

第二幕 · 分词这一关

关键：同一段文字，BPE 的切法不唯一

一个实测例子

学生采样时逐词生成，得到一个 3 字 token：
        [ 了一位 ]                    → 1 个 token

把它解码成文字「了一位」，再让分词器重新切：
        [ 了 ][ 一位 ]                → 2 个 token
为什么会不一样

采样是一个一个往外蹦的，可能产出一条「合法但不是分词器首选」的切法；
而重新分词会给出分词器自己偏好的那一种。文字一模一样，token 数从 1 变成 2。

第二幕 · 分词这一关

后果：位置全错，而且不报错

教师返回的是逐位置的分布

token 数一变  →  教师的第 k 行不再对应学生的第 k 个位置  →  后面全部错位
而这种错位不会抛任何异常，loss 还能正常下降，只是学的东西整体偏了一格。
所以做法是

把学生生成的原始编号序列直接交给教师，全程不经过文字。
这个做法叫 token-in-token-out。

第三幕 · 采样怎么塑造学生的轨迹

temperature 做的是：改变分布的形状

把分数转成概率之前，先除以一个数

概率 = softmax( 模型原始分数 / T )      T<1 更尖 · T>1 更平 · T→0 变成贪心
T = 0.7 更尖最高 0.948 · 熵 0.27
T = 1.0 原始最高 0.833 · 熵 0.71
T = 1.5 更平最高 0.627 · 熵 1.31

最关键的一点：温度不排除任何词。再小概率的词，只要原来非零，改温度之后依然非零。

熵：衡量分布「有多不确定」。熵小 = 集中在少数词上，熵大 = 平均分散。
第三幕 · 采样怎么塑造学生的轨迹

top_k / top_p 做的是完全不同的事：删候选

参数规则特点
top_k = k只留概率最高的 k 个词候选数固定
top_p = p按概率从大到小累加，累到 p 就停候选数自适应
和温度的本质区别

它们把一部分词的概率直接置零，然后在剩下的里重新归一化。
被保留的词之间，相对比例完全不变 —— 所以它们改的是候选集合，不是分布形状。

第三幕 · 采样怎么塑造学生的轨迹

剩下的候选，是按概率抽签，不是选最大的

截断之后重新归一化，然后掷一次骰子

剩 3 个候选：   深色 0.62      黑色 0.29      长裙 0.09
                    ↓             ↓             ↓
               62% 的机会      29% 的机会    9% 的机会

所以每一步都是随机的。同一个问题跑两遍，会得到不同的句子。
「永远选最大的」是另一种做法（贪心解码），相当于把温度降到 0。

第三幕 · 采样怎么塑造学生的轨迹

两者 不独立 —— 降温会自动让 top_p 少留候选

温度最高概率熵top_p=0.9 实际留下
T = 0.70.9480.271 个词截断等于没起作用
T = 1.00.8330.712 个
T = 1.50.6271.315 个同一个 0.9，效果完全不同

同一组分数、同一个 top_p=0.9，因为温度不同，候选数从 1 个变成 5 个。
所以「我把 top_p 设成 0.9」这句话本身不构成一个确定的采样行为，必须连温度一起说。

第三幕 · 采样怎么塑造学生的轨迹

我们实际用的配置（从训练日志里解析出来的真实值）

三个参数

temperature = 0.9      略微锐化
top_p       = 1.0      累加到 100% 才停，等于谁都不删
top_k       = -1       不限制个数
合起来的意思

候选集就是整个词表，248320 个词一个都没被排除。

第三幕 · 采样怎么塑造学生的轨迹

「不截断」到底意味着什么

不能按「很难被抽到所以可以忽略」来理解

一条 30 词的回答  =  30 次抽签
一次训练          =  成千上万条回答
                     ↓
        小概率事件在这个规模下一定会发生
每一个概率非零的词，都真的有机会被抽到，哪怕概率只有 0.001。

这个选择的两面

好的一面学生会走到它真实会犯错的地方，教师就能在那些位置纠正 —— 这正是 on-policy 唯一能提供、off-policy 拿不到的东西
坏的一面会产出低质量甚至退化的句子（第六幕有真实例子），这些轨迹信息密度低
还有一点线上推理一般是要截断的。训练和推理的采样分布不一致，评估结果的可比性要打个问号
第三幕 · 温度到底在哪起作用

「温度」在这套流程里 一共出现三次

位置出现在哪作用
①学生采样时决定学生生成时分布多尖  →  真的有影响
②教师打分的请求里只作用于那 1 个被丢弃的生成 token  →  毫无影响
③算 loss 时对师生两侧同时缩放  →  真的有影响
①和③是同一个参数，所以没法只调其中一个。

做「采样截断策略」对照实验时，该动哪个

参数影响范围能不能用
--temperature采样 + loss（连梯度尺度一起变）不行，一次改了两个变量
--top_p / --top_k只影响采样，不进 loss可以
彻底的解法：加一个 --loss_temperature，默认回落到 temperature —— 几行改动，两个旋钮就独立了。
第四幕 · loss 怎么设计

要让学生「靠拢」教师，先得有把尺子

第一步：单个词上的分歧怎么衡量

同一个词，两边概率之比取对数：   log( 学生概率 / 教师概率 )
情况算出来含义
学生 .40  /  教师 .40log(1) = 0两边一致，没有分歧
学生 .40  /  教师 .04log(10) = +2.30学生说得比教师多得多
学生 .04  /  教师 .40log(0.1) = −2.30学生说得比教师少得多

注意这是逐词算的。教师和学生在这个位置上各自都是一个 24 万维的分布，
所以你手里会有 24 万个分歧值 —— 而不是一个数。

第四幕 · loss 怎么设计

第二步：24 万个分歧值，得汇总成一个数

为什么必须汇总：loss 必须是一个标量才能反向传播

教师分布 = [ 24 万个概率 ]   学生分布 = [ 24 万个概率 ]
逐词分歧 = [ 24 万个数 ]  ——→  ?  ——→  1 个 loss

直接取平均行不通

24 万个词里绝大多数两边都接近 0（既不该说、学生也没想说），这些分歧值是噪声 —— 等权重平均会把真正重要的那几个词淹没。
所以要加权求和 —— KL 的定义就是这么来的

KL(P‖Q) = Σ P(词) × log( P(词) / Q(词) )

用第一个参数 P 自己的概率当权重。P 大的词认真算，P 接近 0 的词几乎不看。

第四幕 · loss 怎么设计

于是就有了 一个必须做的选择：用谁当权重

写法权重用谁的于是它在检查什么
forward KL
KL(教师‖学生)		教师 在教师认为重要的位置上，学生够不够
reverse KL
KL(学生‖教师)		学生 在学生想说的位置上，教师认不认

这就是 KL(P‖Q) ≠ KL(Q‖P) 的来源 —— 不是数学瑕疵，是一个设计决定。
两种都叫 KL，但它们在检查完全不同的东西。

第四幕 · 两种 KL 的机制

理解这件事只需要 一句话

权重为 0 的地方，再大的分歧也会被乘成 0。

于是同一种错误，换个权重，罚得完全不同

哪种错误 用教师当权重（forward） 用学生当权重（reverse）
教师说该有，学生却没有
教师 .45，学生 ≈ 0		 罚得极重
权重 .45 很大，分歧趋于无穷		 几乎不罚
权重是学生的 ≈ 0，整项被乘没了
学生说得起劲，教师却不认
学生 .40，教师 .02		 几乎不罚
权重是教师的 .02，很小		 罚得重
权重 .40 很大，分歧 +3.0
两条对角线上的结论完全相反 —— 这就是两种 KL 会得出相反结论的全部原因。
第四幕 · 两种 KL 的机制

于是两种 KL 把学生逼向相反的方向

beta=0forward KL

逼着学生把教师提到的每一种说法都覆盖到。

→ 概率被摊开（mass-covering）

副作用：学生在教师没提的词上乱放概率，不受惩罚

beta=1reverse KL

逼着学生只说教师认可的话。

→ 概率被收窄（mode-seeking）

副作用：学生完全忽略教师的某些说法，不受惩罚

记忆句：forward 怕漏，reverse 怕错。
但别停在口诀上 —— 接下来三页算给你看。

第四幕 · 落到语言模型上

刚才那个「中间那块」在真实数据里是什么

回到开场那张表的位置 7

教师：房间里 .250   室内 .172   客厅 .151   房间 .118   房间内 .081
好几种说法都对。语言天然如此：说到这里，你可以起「房间里…」也可以起「客厅…」—— 都对，但你必须选一个。所以那两个「峰」就是多种都合理、但互不兼容的续写方式。
forward KL 摊开 → 说含糊话
  • 为了覆盖所有说法，概率被摊平
  • 采样时落到几种说法的夹缝里 —— 单看每个词都沾点道理，连起来不像人话
→
reverse KL 收窄 → 说确定话
  • 挑一种教师认可的说法，把概率压上去
  • 稳定落在一种连贯的说法里；代价是多样性下降
我们选 reverse KL（beta=1），因为要的是确定、不啰嗦的输出。
第四幕 · 落到语言模型上

一个有用的锚点：经典蒸馏用的就是 forward KL

教科书里那个「用教师的软标签做交叉熵」

它和 KL(教师‖学生) 只差一个常数（教师自己的熵），优化起来完全等价。
所以 beta=0 就是经典 KD。

为什么 on-policy 反而普遍偏向 reverse KL

因为两者目标不同：
经典 KD 想让学生逼近教师这个分布；on-policy 想让学生产出好句子。
而「学生产出的句子好不好」，恰好就是用学生自己的概率当权重在衡量的东西。

loss 实际是怎么算的 —— 三步

源码里的三步（gkd_loss.py）

① gather：用教师那 64 个词的编号，从学生的 24 万个分数里挑出 64 个
s_logits = gather(student_logits, teacher_topk_indices)     ← 其余 248256 个全部丢弃

② 两侧同时除以温度
s_logits /= temperature ； t_logits /= temperature

③ 各自在这 64 维上重新归一化，然后算 KL
s_log = log_softmax(s_logits, dim=-1)     ← 64 个数重新加和成 1
t_log = log_softmax(t_logits, dim=-1)
第 ③ 步那个「重新归一化」是关键

教师原本返回的是整个词表上的概率，那 64 个数加起来不到 1。
log_softmax 把它们重新归一化成 1 —— 等于假装词表只有这 64 个词。下一页看它的后果。

所以问题 比「看不见」更严重

重归一化做了什么

它把学生剩下的那 10% 放大成了一个完整分布 —— 于是学生「看起来」和教师很像，

top-k 换的是「监督信息量」，sampled-token 换的是「极低成本」。 我们要教分布形状，所以走 top-k。

那 k 该取多少 —— 用数据回答，不靠猜

k 线性决定传输量：k=16 → 128 B / 位置；k=64 → 512 B；k=256 → 2 KB。
而 hallu 实测均值 0.07%，说明 64 已覆盖学生几乎所有选择，加大 k 是纯浪费；涨到 1~2% 才是该加 k 的信号。

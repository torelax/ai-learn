# 论文阅读笔记写作与 Notion 同步指南

## 交付目标

按三个互补部分交付：论文全文中英逐段对照、忠于论文的中文精炼版，以及独立的补充解读。精炼版让读者快速读完作者的完整技术叙事；补充解读用于解释、比较和实践推演；双语全文保留回查原文的能力。

标准样例取自**仓库中的** `docs/reports/embedding/E5-Mistral/zh.md` 与 `docs/reports/embedding/Qwen3-Embedding/zh.md`，不是 Notion 展示。结合这两篇原论文及各自笔记，理解如何将原文变得精炼、易读、易懂：基本保留原论文全部章节、小节与论证顺序，在相应位置压缩段落，保留核心公式、原图、训练设置和充分的实验表格。不将所有论文重排为统一模板，也不以个人观点或工程建议替代作者叙事。

重做某篇时，先对照原论文列出主文的章节与小节，再在相应位置精炼：作者分别讨论的数据构建、训练阶段、任务协议、实验、消融和讨论应分别保留。不要把不同论文一律改成“背景—方法—主表—个人建议”的模板，也不要只补齐标题而缺少原节的技术内容。必要的解释就近服务于原文；跨论文判断和部署推演另放补充解读。

## 文件职责

- `<方法名>详解.md` 或已有具名报告：忠于论文的中文精炼版，作为 Notion 主体的同步源。已有文件原地更新，不另起重复的“精炼版”文件。
- `<方法名>解读.md`：独立的补充分析。直觉推导、教学例子、跨论文比较和实践建议放在这里；解释性公式与自拟例子明确标示，不当作原文内容。
- `zh.md`：完整的中英逐段对照。同一段英文后紧接对应中文；公式可共用，图表保留双语 caption，参考文献保留原始书目信息。不要默认拆成英文和中文各一篇，不用精炼版覆盖全文。
- `figs/` 与论文全名 PDF：保留论文原资产及阅读所需图片。
- 采集源、临时脚本、核查和同步记录：放在仓库外 `work/`；不提交审核清单、选题笔记等过程材料。实际引用仍在正文中保留论文和官方链接。

E5-Mistral、Qwen3-Embedding 等历史文件暂不因本规则统一改名或迁移。后续新写、或用户明确要求重做的论文采用上述职责；既有成对 `en.md` / `zh.md` 也不顺手批量重排。全文中英对照覆盖主文、附录、图表、脚注和参考文献，说明源版本与实际翻译/校订范围。

## 论文研读与技术总章的两层组织

一篇论文的精炼版回答作者的问题、方案、实验与局限，按原文技术叙事压缩全篇，保留必要附录内容。它不是逐句全文翻译，也不是观点文章。额外的解释性推导与实践分析放入独立解读；`zh.md` 则提供英文与中文逐段对应的全文。

技术总章回答如何理解和使用一种技术，可以结合多篇论文、官方文档和有实验依据的技术博客，讨论超参、适配位置、工程与部署取舍。原文结论和现代实践建议分清，避免把单篇配方当成普遍默认值。

LoRA 专题已确认：三篇论文的具名详解分别进入全局 Paper 库；`LoRA技术深度调研报告.md` 对应 Fine-Tune 原页的 LoRA 技术部分。Fine-Tune 的 Ref 用 Paper 链接视图及类型/微调分类筛选呈现论文，正文引用其阅读页；不把完整研读复制成另一套技术文章。提示微调综述保留既有独立页。

## 组织内容

### 文首 Callout 与论文简介

标题标明论文或方法。Callout 首先用一句话讲清方法思路或具体做了什么，再给出论文、时间和代码等必要入口。可以把模型、语言、任务等合并成一行，也可以按论文特点调整字段；不固定凑齐 backbone / modality / languages 等栏目，不在多个字段中重复同一信息。目标是短小、自然、有辨识度。

Callout 后紧接 **论文简介**，用 1–2 个短段落按“背景与待解决问题 → 核心方法及关键步骤 → 代表性测试结果 → 主要局限”组织，约 200–350 字可作参考，不机械凑篇幅。方法要简洁而系统，结果保留指标和比较条件，局限点出最影响应用的一项即可；证据不足时如实表述。简介是全文导读，之后仍展开完整方法、实验与消融，不用短简介取代阅读笔记。避免在文首放读者任务、交付状态、审计数字、同步日志。

### 背景与相关工作

说明现有路线、具体瓶颈和本文切入点。只展开理解本文所需的前置工作，用比较说明关系，例如“ColBERT 定义多向量交互，ColBERTv2 压缩表示，PLAID 优化检索执行”。

### 方法

沿原文方法章节与小节展开，把输入、表示、机制、流程和实现的依赖关系讲清；可在对应段落内调整措辞和补足前置解释，不另起一套替代原文的章法。定义符号、维度、公式和操作，必要时就近给简短直觉或例子；较长的教学推导另放补充解读。论文原图放在讨论该机制的位置，图后用中文说明组成、流程和意义。

不把方法压缩成几个术语，也不把全文写成纠错清单。原作中影响理解的歧义在对应位置简短注明；公式使用一致的轴和符号，解释性重写与原式清楚区分。

### 实验与分析

交代数据集与任务、训练数据/模型来源、评测指标、比较方法及实验设置。系统论文没有新训练时，说明使用了哪些已有 checkpoint，不硬凑训练配方。

主结果与消融尽量保留足够完整的对照表，并紧接解释“比较了谁、变化多大、支持什么结论”。有不同深度、数据配置或硬件设置时，保留相应条件；引用原图表编号便于回查。数值来自论文还是自己的实验应清楚，但不反复插入未复现声明。

### 结论与局限

回到本文贡献，说明质量、速度、规模或成本的权衡。局限随证据写清，跨任务迁移建议与扩展分析放在独立补充解读。文章不附过程性“请审核”“完成情况”“下一步同步”段落。

## 排版

- 使用语义章节标题，不加章节数字序号；原论文的 Figure/Table/Equation 编号可保留。
- Notion 页面使用自身自动展示的目录，不添加手写目录或 `table_of_contents` 目录块。
- 当前 Notion 连接器的行内公式使用 `$公式$`，公式内容中不要包反引号或中文引号。旧版 enhanced Markdown 文档中的 `$` + 反引号 + 公式 + 反引号 + `$` 写法会在当前解析器中把反引号保留到公式内，显示为多余引号。块级公式仍用独立行的 `$$`。同步前先在待更新正文中确认一处公式往返正确；转换时保护代码块和块级公式，不能对整个页面盲目替换。回读时分别检查普通段落、列表和表格中的行内公式，不只检查块级公式或中文正文一致性。
- 加粗用于核心机制、关键配置和重要结论；列表用于步骤或并列项目，解释和推导仍用完整段落。
- 正文嵌入关键原图及中文解释，表格保留单位、指标、缺失值和必要脚注。
- 引用论文、官方代码或真正相关的已有笔记，不把本地日志、审核清单作为必读链接。

## Notion 同步

1. 先完成本地三类内容。每篇论文的 Paper 主阅读页全文呈现精炼版；补充解读全文放在其独立子页面，并将子页入口放在主页面开头。中英对照全文仅保留在仓库，Notion 不放翻译正文、附件、折叠内容或翻译链接。不创建研究过程、审核清单、选题依据或翻译子页。
2. Embedding 使用 `Embedding&Rerank → Reference → Paper`，data source 为 `collection://0391fb9a-5dfb-4b28-b7dc-84cb27713890`；LoRA / PEFT 单篇论文也使用该全局 Paper，按 `Fine-Tune` 子领域与 `Fine-Tuning` 标签筛选；其他非 Embedding 首次落点不明时再问用户。
3. 搜索并读取已有对应页面。存在用户自写内容、或用户要求追加时，保留原页所有既有块；首次补充在其后导入完整精炼版，后续修订只更新已识别的 Agent 导入范围，不再追加第二套正文。不得用整页替换、重排或清理来覆盖用户笔记。此时解读子页入口放在新增研读部分的开头，保留原页顶部。更新前后核对原内容、图片与代码未改动。其余由 Agent 独立维护的阅读页优先原地更新，保留页面 URL 及既有入口；用户明确要求变更归属时，优先移动已有页并补齐数据库属性。ModelCard 只添加或保留该阅读页的引用。
4. 精炼版与补充解读分别全文同步到主阅读页与解读子页，允许 Markdown 到 Notion 的版式转换；图片上传同一批原图，已有正确图片可复用。仓库正文末尾的翻译链接不带入 Notion；不得用摘要替代正文，也不得把相对路径转换成无效网页链接。
5. 同步前识别并记录上次导入的正文范围和已有用户内容，只更新该范围，禁止每次重做都在页尾再追加整篇。优先定点更新；仅在整页归属已确认或用户明确授权时整页替换，保留所有原生子页/数据库标签。遇到重复，先与仓库历史及旧同步版本比对以确认来源；在用户授权范围内合并重复的 Agent 正文，保留用户新增、改写与无法确认归属的段落。
6. 回读核对正文、公式、表格、图片和页内结构；结果保存在本地同步记录中，不为验证另建 Notion 页面。
7. 不删除无关页面或历史内容。用户明确要求清理本次多建的子页时，仅处理指定子页；已有清理授权不重复索要。未获授权时保持内容并询问。

## 完成标准

精炼版能独立读懂论文全篇，解读有单独边界，双语全文在同一文件逐段对应；仓库与 Notion 的精炼正文和补充解读分别保持一致，图片、公式与表格可用；翻译只在仓库保留，解读子页入口在 Notion 主页面开头。回复用户时给阅读页链接、主要变化及实际验证结果即可。

# 论文阅读笔记写作与 Notion 同步指南

## 交付目标

交付一篇能独立读懂论文的中文阅读笔记：讲清作者要解决的问题、方法如何工作、实验说明了什么，以及方法的适用范围。正文以论文的技术叙事为主线，保留有助理解的推导、例子、图表和关键实验细节。

风格参照 `docs/reports/embedding/E5-Mistral/zh.md`：按背景、相关工作、方法、实验、消融、结论逐步展开；方法中解释术语与公式，表格后解读结果，用适量加粗和短列表突出重点。借鉴其展开方式，不照抄其中的事实判断，也不强制每篇论文套用完全相同的章节。

## 文件职责

- `<方法名>详解.md` 或已有具名报告：唯一的阅读笔记正文，也是 Notion 同步源。已有文件继续原地更新，避免再生成一份重复笔记。
- `zh.md`：论文中文翻译；`en.md`：英文原文转写（如已提供）。翻译保留原文结构，补充解释标明为译注，不用阅读笔记覆盖翻译。
- `figs/` 与论文全名 PDF：保留论文原资产及阅读所需图片。
- `sources/`、脚本、获取日志和核查记录：本地过程资料。通常不需要新增面向读者的审核文档，不自动同步到 Notion。

E5-Mistral 的 `zh.md` 是本次指定的风格样例，历史文件先保留；以后新写的阅读笔记仍使用具名文件，不扩大这种职责混用。用户另行要求翻译、附件或过程资料时，按要求提供。

## 论文研读与技术总章的两层组织

一篇论文的研读回答作者的问题、方案、实验与局限，可以加入忠实的摘要译文和按原文结构的中文译述，并将解释性推导标明为解读。译解不自动等同于逐句全文翻译；完整逐句翻译仍使用 `zh.md`，不能用阅读摘要替代。

技术总章回答如何理解和使用一种技术，可以结合多篇论文、官方文档和有实验依据的技术博客，讨论超参、适配位置、工程与部署取舍。原文结论和现代实践建议分清，避免把单篇配方当成普遍默认值。

LoRA 专题已确认：三篇论文的具名详解分别进入全局 Paper 库；`LoRA技术深度调研报告.md` 对应 Fine-Tune 原页的 LoRA 技术部分。Fine-Tune 的 Ref 用 Paper 链接视图及类型/微调分类筛选呈现论文，正文引用其阅读页；不把完整研读复制成另一套技术文章。提示微调综述保留既有独立页。

## 组织内容

### 文首 Callout 与论文简介

标题标明论文或方法。Callout 首先增加 **简述**：用一句话说明论文的方法思路或做了什么，避免只写“效果好”“提出新模型”。随后列论文链接、代码/项目、作者/时间、骨干、模态和语言；有必要时补 1–3 个前置工作链接。

Callout 后紧接 **论文简介**，通常约 200–350 个中文字、1–2 个短段落，按“背景与待解决问题 → 核心方法及关键步骤 → 代表性测试结果 → 主要局限”组织。方法要简洁而系统，结果保留指标和比较条件，局限点出最影响应用的一项即可；证据不足时如实表述。简介是全文导读，之后仍展开完整方法、实验与消融，不用短简介取代阅读笔记。避免在文首放读者任务、交付状态、审计数字、同步日志。

### 背景与相关工作

说明现有路线、具体瓶颈和本文切入点。只展开理解本文所需的前置工作，用比较说明关系，例如“ColBERT 定义多向量交互，ColBERTv2 压缩表示，PLAID 优化检索执行”。

### 方法

按方法的依赖顺序展开：输入与表示 → 核心机制 → 完整流程 → 实现要点。先解释直觉，再定义符号、维度、公式和操作；必要时给小例子或伪代码。论文原图放在讨论该机制的位置，图后用中文解释它的组成、流程和意义。

不把方法压缩成几个术语，也不把全文写成纠错清单。原作中影响理解的歧义在对应位置简短注明；公式使用一致的轴和符号，解释性重写与原式清楚区分。

### 实验与分析

交代数据集与任务、训练数据/模型来源、评测指标、比较方法及实验设置。系统论文没有新训练时，说明使用了哪些已有 checkpoint，不硬凑训练配方。

主结果与消融尽量保留足够完整的对照表，并紧接解释“比较了谁、变化多大、支持什么结论”。有不同深度、数据配置或硬件设置时，保留相应条件；引用原图表编号便于回查。数值来自论文还是自己的实验应清楚，但不反复插入未复现声明。

### 结论与局限

回到本文贡献，说明质量、速度、规模或成本的权衡。局限随证据写清，迁移建议标明为阅读理解或待验证方向。文章不附过程性“请审核”“完成情况”“下一步同步”段落。

## 排版

- 使用语义章节标题，不加章节数字序号；原论文的 Figure/Table/Equation 编号可保留。
- 加粗用于核心机制、关键配置和重要结论；列表用于步骤或并列项目，解释和推导仍用完整段落。
- 正文嵌入关键原图及中文解释，表格保留单位、指标、缺失值和必要脚注。
- 引用论文、官方代码或真正相关的已有笔记，不把本地日志、审核清单作为必读链接。

## Notion 同步

1. 先完成本地阅读笔记，再同步同一份正文。默认一篇论文对应一个阅读页，不创建研究过程、审核清单、选题依据、翻译等子页，也不把这些资料堆到文末充当附件。
2. Embedding 使用 `Embedding&Rerank → Reference → Paper`，data source 为 `collection://0391fb9a-5dfb-4b28-b7dc-84cb27713890`；LoRA / PEFT 单篇论文也使用该全局 Paper，按 `Fine-Tune` 子领域与 `Fine-Tuning` 标签筛选；其他非 Embedding 首次落点不明时再问用户。
3. 搜索并读取已有对应页面，优先原地更新，保留页面 URL 及既有入口；用户明确要求变更归属时，优先移动已有页并补齐数据库属性。ModelCard 只添加或保留该阅读页的引用。
4. 全文同步，允许 Markdown 到 Notion 的版式转换；图片上传同一批原图，已有正确图片可复用。不得用摘要替代正文，也不得把相对路径转换成无效网页链接。
5. 回读核对正文、公式、表格、图片和页内结构；结果保存在本地同步记录中，不为验证另建 Notion 页面。
6. 不删除无关页面或历史内容。用户明确要求清理本次多建的子页时，仅处理指定子页；已有清理授权不重复索要。未获授权时保持内容并询问。

## 完成标准

读者在单个页面中就能理解问题、机制和实验结论；仓库阅读笔记与 Notion 图文一致，翻译与过程资料职责清楚。回复用户时给阅读页链接、主要变化及实际验证结果即可。
